# Сервер стека — как на нём работать

Машина: netcup RS 4000 G12, `159.195.46.213`, алиас `stack` в `~/.ssh/config`.
12 ядер · 31 ГБ · 961 ГБ свободно. Поднята 16.08 — [[adr-vybor-servera-netcup-rs-4000-g12]].

**Проверено двумя перезагрузками: всё поднимается само за 40 секунд, 26 проверок из 26.**

## Три способа работать

**Быстрый вопрос** — ответ в терминал мака, сессия живёт один запрос:
```bash
ssh stack 'claude -p "посмотри логи helm за час, есть ли ошибки"'
```

**Полноценная работа** — рабочее место в tmux, поднимается само при загрузке:
```bash
ssh stack
tmux attach -t work      # окна: main · vault · code
claude
```
Выйти, **не убивая работу**: `Ctrl-b`, затем `d`. Агент продолжит, даже если закрыть ноутбук.
Закрыть терминал без этого тоже безопасно — tmux живёт на сервере, а не в окне.

**Роли** — как на маке: `director` · `lead qa` · `stack`.
`open-lead qa` открывает лида отдельным окном tmux (научено 16.08; до этого умело только
вкладку iTerm2, то есть на сервере компания ролей не поднялась бы вовсе).

## Смотреть за работой

```bash
ssh stack -t 'tmux attach -t work'          # подключиться (можно с двух устройств сразу)
ssh stack -t 'tmux attach -t work -r'       # только смотреть, ничего не нажать случайно
ssh stack 'tmux capture-pane -pt work:main | tail -40'   # заглянуть, не подключаясь
```

## Управление

```bash
ssh stack 'bash ~/full-check.sh'                          # 26 проверок
ssh stack 'bash ~/.claude/hooks/stack-doctor.sh | tail -3'
ssh stack 'uptime; free -h; df -h /'
ssh stack 'sudo systemctl reboot'                         # возвращается за 40 секунд
ssh stack 'bash ~/.claude/hooks/grant-write.sh project_hub 30'   # окно записи на readonly-сервер
```

## Что стоит и почему именно так

| Что | Решение и причина |
|---|---|
| **Рабочее место** | systemd-юнит уровня пользователя + `loginctl enable-linger`. Без lingering службы пользователя стартуют только при входе по ssh и гаснут при выходе — то есть наоборот тому, что нужно серверу |
| **Claude Code в окнах** | **не** поднимается автозапуском намеренно: сессия начала бы работать без задачи и без наблюдателя, а стоила бы как обычная |
| **Docker** | из официального репозитория, не из Debian: в дистрибутивном пакете отстаёт compose v2. Пользователь в группе `docker` — это равносильно root, но альтернатива (sudo на команду) остановила бы ночной прогон на запросе пароля |
| **Логи Docker** | ограничены 50 МБ × 3 на контейнер. Один разговорчивый контейнер за неделю кладёт диск |
| **Уборка Docker** | таймер раз в неделю, `prune -af --filter until=168h` |
| **Синхронизация памяти** | Syncthing, ~25 секунд в обе стороны, `.git` из синка исключён (git и Syncthing вместе портят репозиторий, а не конфликтуют по файлу) |

## Что НЕ поднимается само — и это верно

**Claude Code и агенты.** Окна tmux заводятся пустыми. Автозапуск агента означал бы работу без
задачи: он начнёт что-то делать, никто не увидит, а деньги спишутся.

## Известные пределы

- **tmux-сессии не переживают падение самой машины** — переживают перезагрузку, потому что их
  поднимает systemd, но содержимое окон при этом теряется. Работа, которую нельзя терять,
  должна лежать в памяти или в git, а не в буфере окна.
- **Секреты на Linux лежат файлами с правами 600, без шифрования** —
  [[area-dostupy-servera-steka]]. Закрыло бы класс только шифрование диска, которого нет.
