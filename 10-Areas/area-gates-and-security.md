# Гейты и безопасность

Слой, который физически не даёт агенту сделать необратимое: правку клиентского кода мимо
делегирования, запись в собственный конфиг через шелл, пуш в рабочий репозиторий, действие на
проде вне разрешённого окна. Это не правила в персоне — это код, который выполняется до вызова
инструмента и возвращает отказ.

**Принцип области:** правило, живущее только в тексте персоны, — это надежда. Гейтом считается
только то, что механически проверяется и умеет сказать «нет».

## Как устроено сейчас

| Что | Где | Роль |
|---|---|---|
| `guard.sh` | `~/.claude/hooks/guard.sh` | единый `PreToolUse`-гейт, четыре правила: A2 · CONFIG · PUSH · PROD/STOP |
| `gate-check.sh` | `~/.claude/hooks/gate-check.sh` | детерминированный гейт перед мержем и деплоем |
| `stack-doctor.sh` | `~/.claude/hooks/stack-doctor.sh` | самопроверка всего стека; больше половины проверок — юнит-тесты хуков на сформированных payload |
| `permission-denied.sh` | `~/.claude/hooks/permission-denied.sh` | журнал отказов прав с редакцией секретов; `--report` показывает все отказы с причинами |
| `secret.sh` | `~/.claude/hooks/secret.sh` | доступ к Keychain: `set` / `get` / `env` / `list` |
| `autonomy.sh` | `~/.claude/hooks/autonomy.sh` | окно автономии: `open` / `status` / `close` |
| deny/allow-правила | `~/.claude/settings.json` | подстрочный слой; используется только там, где структурно не выразить |

**Четыре правила `guard.sh`:**

- **A2** — роль `director` не правит клиентский код сама, делегирует. Покрывает не только `Edit`/`Write`
  и запись через Bash, но и **write-инструменты MCP** (Serena, basic-memory): прежний матчер по
  именам `Edit|Write|MultiEdit` весь MCP-слой пропускал, хотя `CLAUDE.md` сам предписывает работать
  символьными операциями. **Субагенты исключены по `agent_id`** — без этого гейт блокировал бы
  `implementer`'а, которого ГД же и спавнит, то есть сам себя.
- **CONFIG** — запись **через Bash** в периметр, управляющий поведением агента (`settings.json`,
  `hooks/`, `agents/`, `commands/`, `workflows/`, `CLAUDE.md`, стек). Через `Edit`/`Write` — можно:
  там правка видна в транскрипте как дифф, который человек может отревьюить, а `echo >` внутри
  цепочки — нет. Логи и рабочее состояние в `~/.claude` периметром не считаются.
- **PUSH** — в рабочие репозитории пушит только человек. Проверяется **структурно**: `cwd`, явные
  флаги `-C` / `--git-dir` / `--work-tree`, смена каталога перед push. Не по имени ветки — `git push
  origin main` выглядит одинаково в любом репозитории.
- **PROD/STOP** — меняющие прод MCP-инструменты (`ssh_execute_sudo`, `ssh_deploy`, `ssh_upload`,
  туннели) разрешены только внутри живого окна автономии. **Fail-closed:** не смог прочитать окно —
  запрет. Файл `~/.claude/AUTONOMY_OFF` перебивает окно.

## Почему так

- **Гейты структурные, а не подстрочные** — [[adr-structural-gates-not-substring]]. Правила по подстроке
  ошибаются на прозе: за один час они заблокировали работу четырежды, и каждый раз формально
  правильно (тестовый payload в команде, `2>/dev/null` рядом с упоминанием пути, путь в тексте
  commit-сообщения, названия самих deny-правил в commit-сообщении).
- **У «не проверено» и «нарушено» разные коды возврата** — [[adr-gate-exit-codes]]. Гейт,
  который на отсутствие входных данных отвечает «чисто», хуже отсутствующего.
- **Kill-switch отдельно от окна.** Окно — про «разрешено на время», `AUTONOMY_OFF` — про «стоп
  сейчас, независимо ни от чего». Открыть окно поверх `AUTONOMY_OFF` нельзя: сначала снять стоп,
  это осознанное действие человека.
- **Форма важна:** вход хука передаётся переменной окружения, python-код — в **закрытом heredoc**
  (`<<'PY'`). При `python3 -c '…'` любой апостроф внутри кода закрывает шелл-строку, bash отдаёт
  код 2, а код 2 для `PreToolUse` = «блокировать». Так `guard.sh` однажды запер сессию целиком.

## Известные грабли

- **Сломанный `PreToolUse`-хук блокирует ВСЁ, включая собственную починку.** Код 2 = блокировать, и
  синтаксическая ошибка bash даёт ровно его. Выход — восстановить файл из git мимо заблокированных
  инструментов: `git -C ~/.claude checkout -- hooks/guard.sh` в обычном терминале, либо из сессии
  через `Monitor` (он не попадает под matcher). Доктор теперь запускает каждый зарегистрированный
  хук с пробным входом и считает код 2 провалом.
- **Deny сильнее allow, и матчится по всей строке команды.** Подстрочный запрет перебивает
  разрешающее правило — подтверждено эмпирически. Практический вывод: **запрещённую строку нельзя
  упоминать даже в прозе внутри команды** — коммит с фразой про опасную команду блокируется, хотя
  ничего не делает.
- **`grep -c` возвращает код 1 при нуле совпадений**, а `bad`, вызванный внутри пайпа, инкрементит
  счётчик в субшелле — инкремент теряется. Так доктор однажды печатал ПРОВАЛ и внизу рапортовал
  «всё чисто». Гейт, который умеет врать, опаснее отсутствующего: на нём держится вся дисциплина.
- **Мозг (`brain-up`) с `cwd` внутри кодового корня попадает под собственный A2-гейт** — не мог ни
  создать файл, ни записать заметку, если в её тексте попадалось слово из кодового корня. Гейт
  срабатывал правильно, стоял не в том месте мозг: его дом — vault, код читается через `--add-dir`.
- **Ложное срабатывание защиты конфига по «маркер + глагол где угодно»** — тот же антипаттерн
  подстрочного правила, воспроизведённый внутри самого гейта.

## Как проверить, что живо

```bash
bash ~/.claude/hooks/stack-doctor.sh          # всё сразу; читай вывод, а не только последнюю строку
bash ~/.claude/hooks/gate-check.sh <worktree> --scope <файл> --metrics <json>
bash ~/.claude/hooks/permission-denied.sh --report
autonomy status
```

Норма: **ноль провалов**. Варны — принятый тех-долг, они перечислены в [[tech-debt]]. Сколько
всего проверок, доктор печатает сам; здесь это число намеренно не записано — инвентарные числа в
прозе врут уже на следующем коммите.

## Границы

Гейты **не проверяют суждение**: подлинность данных, работает ли фича по существу, соответствие
замыслу плана. `gate-check.sh` печатает это явным списком «чего не проверяет вообще» — чтобы не
притворяться, что проверено. Это остаётся на `verifier` и `controller`.
