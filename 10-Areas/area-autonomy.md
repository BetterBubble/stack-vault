# Автономка

Три разные вещи, которые легко перепутать, потому что все три про «работает без меня»:
**always-on** (мак не спит, мозг жив), **телефон-контроль** (управление с телефона и пуши) и
**ночной прогон фичи** (агенты доводят работу до результата, пока человек спит).

**Принцип области:** агент не знает, что человек спит. Поэтому разрешение на прод выдаётся **на
время и под задачу**, а не «выдано и следим».

## Как устроено сейчас

| Слой | Чем реализовано | Ключевое |
|---|---|---|
| Always-on | `brain-up` в `roles.zsh` → `caffeinate -s` | держит систему бодрой **на зарядке при любом состоянии экрана**, пока мозг жив; `pmset` трогать не нужно |
| Телефон-контроль | `claude --remote-control "<имя>"` + нативное приложение Claude, вкладка Code | управление маршрутизируется через API, выполнение — на маке |
| Presence | `CLAUDE_CLIENT_PRESENCE_FILE` | **файл ЕСТЬ → present** (пуши глушатся), **НЕТ → away** (эскалация пушем). Детерминированно, важен файл, а не фокус окна |
| Окно автономии | `autonomy open/status/close` → `~/.claude/AUTONOMY_WINDOW`, лог в `~/.claude/autonomy.log` | 1–24 ч, по умолчанию 8 |
| Kill-switch | `touch ~/.claude/AUTONOMY_OFF` | мгновенно глушит прод-действия всем агентам; перебивает окно |
| Ночной пайплайн | `~/.claude/workflows/autonomous-feature.js`, скилл `autonomous-feature` | реализация → проверка → гейт → фикс-повтор, `maxAttempts: 3` |
| Разрешение на прогон | durable-флаг `autonomy: on` в plan-заметке | **не из чата** |

**Порядок шагов пайплайна — и есть защита:**

1. **проверка окна** — до всего остального; нет окна → деплоя нет, а вся остальная работа идёт; прогон не начинается вовсе только при AGENTS_OFF, а не «попробует»;
2. **бэкап, и обязательно проверенный** — не «сделал бэкап», а «существует, размер разумный,
   восстановимость подтверждена». Непроверенный бэкап хуже отсутствующего: он даёт ложную
   уверенность ровно в тот момент, когда уже поздно;
3. деплой по runbook;
4. проверка на реальных данных, не на фикстурах и не по логам;
5. **артефакт откатa в репозитории — даже если всё прошло успешно.**

## Почему так

- **Мозг живёт на маке, не в облаке.** Работа глубоко локальная: репозитории, локальные MCP,
  vault, ssh-деплой. Облачные routines видят только GitHub-репозитории и не имеют доступа к
  локальным файлам, MCP и серверам. Отдельный box отложен осознанно — мак даёт весь локальный
  доступ за 0 ₽.
- **Пятый шаг (артефакт откатa всегда) — требование Президента, и оно неочевидное.** Обычная логика:
  «сломалось → откатываем, всё ок → идём дальше». Но «всё ок» ночью и «всё ок» через день, когда
  написали пользователи, — разные утверждения. Поэтому команда откатa пишется и коммитится, пока
  контекст ещё жив. **Нет артефакта = прогон неуспешен**, что бы ни показали проверки.
- **Провал ГЕЙТА — до трёх попыток фикса в том же worktree, затем задача помечается и очередь идёт дальше. Провал ДЕПЛОЯ — откат и стоп по этой задаче. Разводить обязательно: «не вставать на первой проблеме» и «не дожимать необратимое» — разные требования.** Дожимать в три
  ночи — ровно то, чего человек не хочет.
- **Деплой по умолчанию `allowDeploy: false`** — остаётся осознанным шагом человека.
- **Ночью роль тимлида исполняет сам Workflow, lead-сессия не создаётся.** Ночной путь короче
  дневного на одно звено, и это влияет на гейты — см. A2 и исключение субагентов.

## Известные грабли

- **Автономка ни разу не запускалась.** `autonomy: on` не встречается в vault ни разу — весь узел
  остаётся спекой. Первый прогон должен быть сухим, на тривиальной фиче: он вскроет то, чего не
  видно в коде. Это главный пункт долга области, [[tech-debt]].
- **Presence-механика — по большей части эмпирика**, а не гарантированный контракт: часть выведена
  наблюдением, точный idle-порог не задокументирован. На ней держится телефон-канал.
- **Сессия, запущенная ДО регистрации мобильного приложения, кэширует `No mobile registered`** и не
  перечитывает на лету. Открыть приложение в старой сессии — мало, нужна новая сессия или
  переподключение Remote Control.
- **Present глушит даже пуши «actions required»** — оба типа подчиняются presence. «Отойти, не
  закрывая окно» ненадёжно: окно в фокусе = present. Надёжный away — сменить приложение, свернуть
  или заблокировать мак.
- **iOS Low Power Mode сильно откладывает app-пуши** (системный «remote control enabled» проходит,
  обычный — нет).
- **На батарее `caffeinate` сон не держит.** Условие always-on одно: воткнут в зарядку.
- **Закрытая крышка без внешнего монитора усыпляет мак.** Обход греет — только при контроле
  температуры.

## Как проверить, что живо

```bash
autonomy status                      # окно открыто? сколько осталось?
cat ~/.claude/autonomy.log           # история открытий и закрытий
ls ~/.claude/AUTONOMY_OFF            # стоп активен?
pmset -g assertions | grep -i caffe  # держит ли caffeinate систему
```

Утром после прогона: `autonomy status` (окно должно закрыться само), доска `00-Board`, журнал
воркеров `00-Board/_workers.md`.

## Границы

Автономка покрывает **фазу исполнения** — воркеры, гейты, деплой. Варка идеи и план требуют
человека: это диалог, а не исполнение. Автоном без апрувленного плана с `autonomy: on` не
запускается — и это защита, а не формальность.
