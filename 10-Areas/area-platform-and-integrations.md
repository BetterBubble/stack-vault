# Платформа и интеграции

Всё, на чём стек стоит и без чего он не поднимется на другой машине: сама установка Claude Code,
адаптер путей, генерация `settings.json`, MCP-серверы, реестр совместимости с версией CLI.

**Принцип области:** портативность проверяется установщиком, а не намерением. «Работает у меня» и
«поднимется на чистой машине» — разные утверждения, и второе надо уметь показать командой.

## Как устроено сейчас

| Что | Где | Портативность |
|---|---|---|
| Ядро-доки, персоны | `~/claude-stack/*.md`, `roles/` | портативно |
| Команды ролей | `~/claude-stack/roles.zsh` (source в `~/.zshrc`) | портативно, читает конфиг |
| Хуки | `~/.claude/hooks/*.sh` | портативно, читают конфиг |
| Регистрация хуков + permissions | `~/.claude/settings.json` | **вне git**, генерируется из `settings.example.json` |
| Дефиниции воркеров | `~/.claude/agents/*.md` | портативно |
| Always-loaded правила | `~/.claude/CLAUDE.md` | содержит немного специфики работы |
| **Адаптер путей** | `~/.claude/agent-stack.conf` | **единственное, что правится при переносе** |
| Профиль работы | `~/claude-stack/profiles/<работа>.md` | заменяется при смене работы |

Адаптер задаёт три пути: `AGENT_VAULT` (рабочий vault), `AGENT_CODE_ROOT` (корень клиентского кода),
`AGENT_WORKTREE_ROOT` (корень worktree воркеров — **обязан быть ВНЕ кодового**).

Установка Claude Code — **нативная**: `~/.local/bin/claude` → `versions/…`, автообновления включены.
Раньше был Homebrew, и он давал `EACCES` при self-respawn; плюс в `.zshrc` стоял
`DISABLE_AUTOUPDATER=1`, который глушил обновления молча.

Бэкап трёх личных репозиториев — на `github.com/BetterBubble`: `claude-stack`, `claude-config`,
`work-vault`. Четвёртый (`stack-vault`) заводится сейчас.

## Почему так

- **Все пути конкретной работы вынесены в один файл-адаптер.** Иначе перенос требует правки
  десятков мест, и часть из них обнаруживается только в проде.
- **`settings.json` генерируется из шаблона.** Это была главная дыра переноса: сам файл не
  версионируется, а без него не работают ни гейты, ни канал сигналов. Установщик подставляет
  домашний каталог в 18 местах.
- **Фоллбэки честно названы дефектом-компромиссом.** В хуках остались дефолты вида
  `${AGENT_VAULT:-$HOME/tacticum-vault}` — без конфига они молча уйдут на путь текущей работы, а не
  упадут. Страховка не в фоллбэках, а в том, что **отсутствие конфига ловится громко**:
  `install.sh --check` и `stack-doctor.sh` оба дают провал, если конфига нет или
  `AGENT_WORKTREE_ROOT` лежит внутри кодового корня.
- **Реестр совместимости `cli-compat.md` завёлся после того, как трижды за один заход выяснилось,
  что стек построен на предположении о поведении инструмента**, а фактическое поведение другое.
  Столбец «как проверено» важнее остальных: **«по документации» и «проверено прогоном» — разные
  уровни доверия**, и путать их дорого.

## Известные грабли

- **`FileChanged` не срабатывает без `watchPaths`**, которые должен отдать другой хук; плюс матчер
  ждёт литеральное имя файла, а не произвольную метку. Хук был зарегистрирован и **не работал
  никогда**. Сейчас в `settings.json` его нет.
- **`SessionEnd` не вызывается на `kill -9`, падении и засыпании** — поэтому чистка реестра ролей
  дополнена проверкой живости по pid.
- **`timeout` хука — в секундах, без него дефолт 600 с**: зависший хук держит сессию.
- **`agent_id` во входе `PreToolUse` присутствует только внутри субагента** — на этом держится
  исключение воркеров из гейта A2. Взято **по документации**, живым прогоном автонома не проверено.
- **Правила `settings.json` — глобы по всей строке команды**, они не отличают операнд от прозы.
  Отсюда весь класс ложных блокировок; в хуках от этого ушли, см. [[adr-structural-gates-not-substring]].
- **allow-правило нужно в двух формах** — `bash /Users/bubblemac/.claude/hooks/…*` и
  `bash ~/.claude/hooks/…*`: матчер сравнивает строку команды и `~` за тебя не разворачивает.
- **`~/.zshrc` не в бэкапе.** Перенос на новую машину теряет подцепку `roles.zsh` и переменные,
  настроенные руками. См. [[tech-debt]].
- **MCP-серверы установщик не ставит** — `basic-memory`, `serena`, `context7` и job-specific
  прописываются отдельно, со своими токенами.

## Как проверить, что живо

```bash
bash ~/claude-stack/install.sh --check       # готовность, ничего не меняя
bash ~/.claude/hooks/stack-doctor.sh         # конфиг, хуки, бэкапы, версии
claude --version                             # сверить с реестром совместимости
```

Перенос на новую машину:

```bash
git clone git@github.com:BetterBubble/claude-stack.git ~/claude-stack
git clone git@github.com:BetterBubble/claude-config.git ~/.claude
bash ~/claude-stack/install.sh
```

Секреты **не переносятся никогда** — они в Keychain, заводятся заново через `secret set`.

## Границы

Область отвечает за то, чтобы стек **поднялся**, а не за то, чтобы он **работал правильно** — это
гейты и доктор. Специфика текущей работы (тенанты, серверы, трекер) живёт в
`~/claude-stack/profiles/<работа>.md` и в рабочем vault, не здесь.
