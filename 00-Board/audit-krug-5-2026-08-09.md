# Аудит стека круг 5 — находки ревизора-ломателя 2026-08-09

Только чтение, кроме этого файла; все пробы — в песочнице скратчпада (подменённый `HOME`,
одноразовые vault, репозитории и кнопка стопа; живые кнопки, реестр и память не тронуты).
Области круга: шесть починок круга 4 · `diff-shorten.sh` · `transcribe-speakers` ·
`worker-log.sh`+`stop-nudge.sh` · добивка: длина строк ростера · шаблоны плана · три починки,
сделанные уже по ходу круга. Восемь доказанных находок, по убыванию последствия.
Пустого круга снова не вышло; главный итог — **починка круга 4 сломала `mcp-doctor.sh` целиком**

## 1. Починка круга 4 сломала `mcp-doctor.sh`: redact вызывается с аргументом, а читает stdin — таблица пуста, серверы ИСЧЕЗАЮТ из отчёта, счётчики врут

**КЛАСС:** починка сломала то, что чинила (худший класс этого цикла: круг обязан был это искать) +
инструмент диагностики съедает собственные данные.

**ЧТО.** `redact()` — это функция-обёртка над `sed`, она читает STDIN и не смотрит на аргументы.
Обе строки починки круга 4 зовут её с АРГУМЕНТОМ: `target="$(redact "$(… .command, .args …)")"`
(`mcp-doctor.sh:505`) и `"$(redact "$cmd ${ARGS[*]:-}")"` (`mcp-doctor.sh:329`). Аргумент
игнорируется, sed читает то, что лежит в stdin, — а в контексте вызова это stdin цикла
`while … done < "$SPEC"`, то есть СПИСОК ОСТАЛЬНЫХ СЕРВЕРОВ. Три следствия разом: колонка target
получает не команду, а огрызок чужой строки SPEC; съеденные строки не доходят до цикла — серверы
пропадают из отчёта; счётчики считают только выживших.

**ВОСПРОИЗВЕДЕНИЕ** (песочница: `.mcp.json` с ТРЕМЯ stdio-серверами, токен заведомо фальшивый):
```
$ HOME=$SB/home MCP_DOCTOR_ROOTS=$SB/mcproot bash mcp-doctor.sh
  ✘ k5-apikey  stdio project→/private/tmp/…  запускается, но не отвечает…   ← target = кусок ЧУЖОЙ строки SPEC
  (k5-argtoken и k5-normal НЕ ПОКАЗАНЫ ВООБЩЕ)
  Живых 0 · сломанных 1                       ← серверов было три
  …
  увидеть настоящую ошибку:                   ← пусто, команда исчезла
$ … | grep -c FAKEPROBE   → 0    (секрет не печатается — но лишь потому, что не печатается ничего)
Механизм в одну строку: printf '' | redact "cat --token sk-FAKE…" → пусто;
printf 'A\nB\n' | { read -r x; redact "arg"; } → съедены строки соседей.
Правильная форма работает: printf '%s' "cat --token sk-FAKE…" | redact → cat --token <скрыто>.
```

**ПОСЛЕДСТВИЕ.** Доктор MCP на любой машине с двумя и более stdio-серверами (у нас их четыре:
context7, basic-memory, serena, ssh-manager) показывает только первый по алфавиту, врёт счётчиками
и не печатает ни одной команды. «Проверить серверы» с этого утра означает «увидеть четверть
картины и поверить ей» — хуже, чем отсутствие доктора, потому что вывод выглядит осмысленным.

**ЧТО ЧИНИТЬ.** В обоих местах передавать текст через пайп: `printf '%s' "…" | redact`
(`mcp-doctor.sh:505` и `:329`). Плюс тест доктора: фикстура с ДВУМЯ stdio-серверами, в выводе
обязаны быть оба имени и имя команды первого — он ловит и «аргумент вместо stdin», и любой
следующий съеденный дескриптор.

**ПОСТСКРИПТУМ (07:33).** Починено по горячим следам круга и ПЕРЕПРОВЕРЕНО той же фикстурой:
все три сервера в таблице, имена команд читаемы (`npx -y some-server --api-key=<скрыто>`,
`cat --token <скрыто>`), невинные аргументы (`--context claude-code hello`) не тронуты, счётчик
«сломанных 3» верен, строка «увидеть настоящую ошибку: cat --token <скрыто>» непуста, секретов в
выводе ноль. Тест доктора на фикстуру с двумя stdio-серверами по-прежнему нужен.

## 2. Баннер старта: пример «6 дней ожидания → 17 конфликтов» в легенде считается ВЕТКОЙ — «веток ждёт мержа» завышено на 1 всякий раз, когда есть протухшая

**КЛАСС:** починка круга 4 закрыла завышение в одной колонке (протухшие) и оставила тот же дефект
в соседней (всего веток); ложная сводка каждый день, когда есть протухшая ветка.

**ЧТО.** `session-start.sh:82` считает все ветки шаблоном `^  [! ] +[0-9]` по кэшу вывода
`pr-queue.sh`. Легенда протухания (`pr-queue.sh:108`) содержит строку-пример
`      6 дней ожидания → 17 конфликтов…` — шесть пробелов и цифра: класс `[! ]` матчит третий
пробел, дальше пробелы и `6`. Строка легенды печатается ровно тогда, когда протухшие есть.

**ВОСПРОИЗВЕДЕНИЕ** (песочница: два репозитория, одна свежая + одна протухшая ветка):
```
$ pr-queue.sh --root $SB/prroot   → 2 строки данных (repo2 «!», repo1 свежая) + легенда
счёт как в session-start: PRQ(протухло)=1 ✓  PRA(всего)=3 ✗ (веток две)
лишняя строка: «      6 дней ожидания → 17 конфликтов и рабочий день на разбор).»
контроль: без протухших PRQ=0 PRA=1 ✓ («все свежие» достижима); пустой кэш и кэш
«очередь мержа: пусто» → баннера нет ✓
```

**ПОСЛЕДСТВИЕ.** Баннер «веток ждёт мержа: 3, из них протухло 1» при двух реальных ветках — в
точности тот сорт всегда-вранья, против которого починку писали: сводке перестают верить.

**ЧТО ЧИНИТЬ.** Требовать ДВЕ числовые колонки подряд (возраст и отставание):
`grep -cE '^  [! ] +[0-9]+ +[0-9]+ +'` — у легенды после «6» идёт « дней», у строк данных всегда
второе число. Тот же вид правки, что в круге 4, — значит нужен и тест на кэш С легендой.

**ПОСТСКРИПТУМ (07:35).** Починено по горячим следам круга ровно так и ПЕРЕПРОВЕРЕНО на всех
четырёх фикстурах кэша: смешанный (протухшая + свежая) → 1/2, только свежая → 0/1, пустой файл →
0/0, «очередь пуста» → 0/0. Держит.

## 3. Проверка «две редакции одной нормы» в доке доктора не ловит ТОТ САМЫЙ исторический текст — маркер искался строчными, а дефект был заглавными

**КЛАСС:** проверка, которая не может провалиться на случае, ради которого написана (моя область №1).

**ЧТО.** Новая проверка (`stack-doctor.sh:946`) ищет след неотредактированной копии грепом
`grep -q "2026-08-05 вернул\|05.08 вернул"` — строчными и без `-i`. Дефект круга 4 (находка 7)
в `agents/controller.md:38` был написан ЗАГЛАВНЫМИ: «решение Президента 2026-08-05 ВЕРНУЛО апрув
плана» — дословная цитата из отчёта круга 4; так же пишет и живой `gate-check.sh:268`. Кириллица
без явного `-i` (а на BSD grep и с ним) по регистру не сворачивается.

**ВОСПРОИЗВЕДЕНИЕ.**
```
$ printf 'решение Президента 2026-08-05 ВЕРНУЛО апрув плана\n' > copy-test.md   # текст дефекта
$ grep -q "2026-08-05 вернул\|05.08 вернул" copy-test.md && echo ПОЙМАНО || echo ПРОПУЩЕНО
ПРОПУЩЕНО
$ printf 'решение 2026-08-05 вернуло апрув\n' | grep -q "2026-08-05 вернул" && echo ПОЙМАНО
ПОЙМАНО      ← строчный вариант ловится, но в живом дефекте его не было
```
Сегодня `agents/controller.md` вычищен (упоминаний 05.08 нет — проверено грепом), поэтому доктор
зелёный законно. Но верни кто-нибудь исходный абзац копипастой из истории — проверка промолчит.

**ПОСЛЕДСТВИЕ.** Ловушка на класс «двух редакций» (трижды случившийся за сутки) не срабатывает на
единственном реально жившем экземпляре класса. Зелёная строка «редакции согласованы» уверяет в
проверке, которой нет.

**ЧТО ЧИНИТЬ.** Явные обе формы в шаблоне: `grep -qE "(2026-08-05|05\.08) ([Вв]ернул|ВЕРНУЛ)"` —
без ставки на юникодный case-folding конкретного грепа. И юнит-тест доктора с фикстурой, где
маркер заглавными.

## 4. Под полным стопом `AGENTS_OFF` проходит `mcp__serena__activate_project` — а активация НЕЗАРЕГИСТРИРОВАННОГО пути СОЗДАЁТ файлы проекта

**КЛАСС:** дыра гейта (5), тот же класс и та же механика, что `canvas` в круге 4: слово не глагол,
шаблон имён не ловит, в явном списке записи нет.

**ЧТО и ВОСПРОИЗВЕДЕНИЕ.** Полный перебор имён живых stdio-серверов через гейт при кнопке в
подменённом HOME (пробы этого круга): все пишущие DENY, все читающие ALLOW — кроме одного спорного:
```
ALLOW mcp__serena__activate_project     ← под стопом разрешён
```
А код установленной Serena (`site-packages/serena/agent.py:1246`,
`activate_project_from_path_or_name`) говорит: «If the argument is a path at which no Serena
project previously existed, the project will be created beforehand» —
`add_project_from_path` пишет конфиг проекта (`.serena/project.yml` + `.gitignore` кэша,
`project.py:64-68`) в целевой каталог и регистрирует проект в конфиге Serena. То есть вызов с
путём — это запись на диск, в том числе в репозиторий.

**ПОСЛЕДСТВИЕ.** Малое по площади (файлы-конфиги, только в момент аварийного стопа), но
направление то, которое комментарий классификатора называет недопустимым: запись проходит мимо
стопа. Инвариант «при AGENTS_OFF не меняется ничего» снова ложен на одном имени.

**ЧТО ЧИНИТЬ.** Добавить `mcp__serena__activate_project` в `MCP_WRITE` (guard.sh, рядом с
`write_memory`): активация уже зарегистрированного проекта под стопом — редкая и дешёвая потеря,
а создание файлов мимо стопа — недопустимая. После этого перебор живых stdio-имён чист полностью.

## 6. Доктор меряет длину строк ростера в БАЙТАХ, а порог и сообщение называют «символы» — для кириллицы порог вдвое строже заявленного

**КЛАСС:** проверка говорит не то, что меряет (мелкая; варн, не провал).

**ЧТО и ВОСПРОИЗВЕДЕНИЕ.** `stack-doctor.sh:962-963` считает `awk length($0)`; awk macOS
(20200816) считает байты:
```
$ python3 -c "print('ы'*250)" > cyr.txt        # 250 символов кириллицы
$ awk '{if(length($0)>m)m=length($0)}END{print m}' cyr.txt   → 500
$ awk 'length($0)>400{n++}END{print n+0}' cyr.txt            → 1   ← «длиннее 400 символов»
```
Ростер — кириллический текст: реальный порог срабатывания ~200 символов, а напечатанный maxlen
завышен вдвое.

**ПОСЛЕДСТВИЕ.** Легитимная строка в 250 символов получит варн «500 символов» — ложная тревога с
неверным числом; варны, которым не верят, пролистываются вместе с настоящими.

**ЧТО ЧИНИТЬ.** Считать символы: `python3 -c` по файлу либо `perl -CSD -ne`. Порог 400 оставить —
он выбран по жалобе на экранную простыню, а экран меряется символами.

## 8. Проверка длины строк ростера никогда не выполняется там, где доктора реально гоняют, — а живой ростер прямо сейчас держит 11 строк за порогом, включая исходную на 7288 символов
