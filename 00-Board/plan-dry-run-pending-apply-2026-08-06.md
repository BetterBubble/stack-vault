# План: README стека знает про `pending-apply`

autonomy: on
апрув: ГД, 06.08 (сухой прогон по прямому заказу Президента, он спит; деплоя нет, контур личный)

**Это сухой прогон ночного пайплайна** — он ни разу не запускался вживую с момента написания
(115→118 тестов есть, живого запуска нет). Кандидат выбран специально безобидным: личный репозиторий,
только документация, деплой запрещён аргументом.

## Что сделаем

В `~/claude-stack/README.md` добавить раздел про каталог `pending-apply/` — что это, когда там
появляются файлы и что с ними делать. Сейчас каталог существует, в нём четыре документа, ждущих руки
Президента, а README о нём не знает вовсе: агент, пришедший на новую машину, о них не узнает.

## Как это будет выглядеть

В README появляется раздел «`pending-apply/` — что ждёт руки Президента» со списком того, что там
лежит сейчас (четыре файла с одной строкой описания каждый) и правилом: файл оттуда исчезает, когда
применён, а не остаётся «на память».

## Что НЕ трогаем

`HANDBOOK.md`, `memory-protocol.md` (неприкосновенный), `agent-company.md` (неприкосновенный),
`roles/`, `settings.example.json`, любые хуки в `~/.claude`, рабочий vault, рабочие репозитории.
Ни одного файла вне `~/claude-stack/README.md`.

scope:
  - README.md

## Приёмка

acceptance:
  - битых_ссылок <= 0
  - изменённых_файлов <= 1

Плюс глазами: `bash ~/.claude/hooks/check-links.sh` даёт «битых 0», а `git diff --stat` показывает
ровно один файл.

## Зачем именно эта задача

Три причины: она реально нужна (четыре документа ждут и о них негде прочитать), она полностью
обратима (одна правка markdown в личном репозитории), и она проверяет **новый гейт апрува плана** на
живом прогоне — строка `апрув:` и раздел «Что НЕ трогаем» здесь есть, значит пайплайн обязан взять
задачу; без них он обязан отказать (это проверено юнит-тестами, но не живым запуском).
