## 2. Что ДОЛЖНО отличаться по построению (слепой rsync запрещён)

- **`~/.claude/settings.json`** — единственный содержательно машинозависимый файл:
  - все пути хуков: `/Users/bubblemac/...` ↔ `/home/alex/...` (в allow-списке и в hooks/statusLine);
  - возможно модель (если выбор opus для сервера намеренный);
  - Stop-хук `voice-response.sh` — только мак (на сервере нет аудио);
  - он и так вне git (в `.gitignore` claude-config как секрет) — переносить только осмысленные дельты руками либо генерировать из шаблона.
- **`~/.claude/commands/transcribe-md.md`** — на маке симлинк в
  `~/.local/share/transcribe-md/...` (и в git он затрекан как symlink, mode 120000!),
  на сервере — материализованная копия. При git-клоне на сервере станет битой ссылкой —
  надо учесть (см. §3).
- **Рантайм/локальное, не синкается никогда:** `history.jsonl`, `projects/`, `sessions/`,
  `session-env/`, `file-history/`, `logs/`, `tasks/`, `teams/`, `.credentials.json`,
  `.secrets.d/`, `settings.json.bak*`, `permission-denied*.log`, `.role-registry` и т.п. —
  всё это уже покрыто `.gitignore` claude-config (политика «игнорим всё, разрешаем явно»).
- `agent-stack.conf` — сейчас идентичен (пути внутри через `$HOME`, абсолютных нет),
  но по смыслу он машинный адаптер: в механизм синка не включать, расхождение в будущем — норма.
- `stack-hosts` / `stack-hosts-readonly` — периметр стека, файлы вне обоих репо; сейчас
  идентичны (readonly на сервере просто отсутствует). Возить руками при изменении или добавить в claude-config.

## 3. Механизм синка навсегда (предложение)

**Git в оба контура; scp умирает как способ доставки конфига.** Половина работы уже
сделана — оба репо существуют, а .gitignore claude-config ровно для этого и написан.

1. **`~/claude-stack` на сервере** — уже клон. Разовое выравнивание:
   мак: закоммитить `tools/mac-*.sh`, `git push origin main` (личный контур — пуш свободен);
   сервер: удалить 8 untracked-строев из §1, `git fetch && git reset --hard origin/main`
   (безопасно: доказано, что самодельных правок нет). Дальше синк = `git pull` на сервере.
2. **`~/.claude` на сервере** — сделать клоном `claude-config` поверх живого каталога:
   `git init && git remote add origin ... && git fetch && git checkout -f main`
   (рабочие файлы уже совпадают с маком, перезапись ничего не потеряет; рантайм защищён
   `.gitignore`). Две каверзы:
   - `commands/transcribe-md.md` — заменить в репо симлинк на обычный файл (симлинк на
     мак-путь на Linux мёртв; на маке реальный файл тоже работает, симлинк был удобством);
     либо занести в .gitignore и держать локально на каждой машине;
   - `settings.json` остаётся вне git на обеих машинах — вести
     `claude-stack/settings.example.json` как шаблон и переносить дельты осознанно
     (или собрать генератор с подстановкой `$HOME` — отдельная задача, не условие синка).
3. **Правило:** конфиг едет только коммитом мак → push → pull на сервере. Один источник
   истины (origin), видна история, нечему «отставать молча» — сегодняшняя ситуация
   (scp довёз 5 файлов из 8) невозможна в принципе. Rsync-скрипт не нужен: он второй
   механизм доставки рядом с git, с собственными эксклюдами, которые разойдутся с
   .gitignore — та самая двойная норма, которой стек избегает.
4. **Проверку дрифта** (md5 трёх периметров мак↔сервер) стоит добавить секцией в
   `stack-doctor.sh` — тогда отставание видно доктором, а не раскопками.
