# Ресерч переноса Claude Code на сервер

Дата ресерча: 2026-08-05. Все ссылки проверены в этот день; там, где источник датирован, дата указана.

## Короткий ответ

**Рекомендую вариант A. Облачный Claude Code (claude.ai/code) как основной дом не подходит — и это не вопрос вкуса, это документированное ограничение.**

| | Что это | Цена/мес | Вердикт |
|---|---|---|---|
| **A. Свой VPS за пределами РФ + `claude remote-control` в tmux** | Claude Code живёт на сервере со всеми хуками, MCP, vault, репозиториями. Ноут — тонкий терминал. Телефон — официальное приложение Claude, которое подключается к сессии на сервере | **€14–21** (Contabo, 8 vCPU / 24 ГБ) или **~2 800 ₽** (Timeweb, Амстердам/Франкфурт, 8 vCPU / 12 ГБ) | **Делать это.** Единственный вариант, где стек переезжает целиком и мобильный доступ работает штатно |
| B. Claude Code on the web (облако Anthropic) | Сессии в VM Anthropic, репо клонируется с GitHub | 0 (входит в подписку, отдельной платы за VM нет) | **Не подходит как основной дом.** Не видит `~/.claude` — ни глобального CLAUDE.md, ни хуков, ни агентов, ни MCP пользовательского скоупа; нет секретов, нет SSH к своим серверам, один репозиторий на сессию. Годится точечно: «сходи в такой-то GitHub-репозиторий и сделай PR» |
| C. Гибрид (Serena/индексация на сервере, сессия локально) | Часть MCP по SSE на сервер, сессия на ноуте | цена сервера та же | **Не стоит усложнения.** Снимает часть памяти, но оставляет главную проблему (сами сессии Claude Code и есть основной едок памяти) и добавляет сетевую хрупкость |

Что мешает варианту A — один пункт, и он решающий: **Россия не входит в список стран, где Anthropic предоставляет доступ** ([supported-countries](https://www.anthropic.com/supported-countries), проверено 2026-08-05: РФ и Беларуси в списке нет; Казахстан, Армения, Грузия, Турция, Сербия, Германия, Нидерланды, Финляндия — есть). Отсюда два следствия, разобранных ниже в «что ломается»: сервер обязан стоять в поддерживаемой стране, а прокси через `ANTHROPIC_BASE_URL` ставить нельзя — он выключает Remote Control.

## Вариант A: свой VPS + Remote Control (рекомендуемый)

### Почему именно Remote Control, а не «SSH с телефона»

Это штатная фича Anthropic, и она делает ровно то, что нужно: Claude Code продолжает работать на **твоей** машине (в нашем случае — на сервере), а браузер и мобильное приложение становятся окном в эту сессию. Из документации [Remote Control](https://code.claude.com/docs/en/remote-control) (research preview, доступно на Pro/Max/Team/Enterprise):

- «your filesystem, MCP servers, tools, and project configuration all stay available» — локальные MCP-серверы и конфигурация никуда не деваются;
- «the conversation and the progress of subagents and dynamic workflows stay in sync across all connected devices» — можно писать из терминала, браузера и телефона в одну сессию попеременно, прогресс субагентов виден на телефоне;
- «if your laptop sleeps or your network drops, the session reconnects automatically» — разрыв связи переживает;
- push-уведомления на телефон: Claude сам пишет, когда долгая задача закончилась или нужно решение; включается в `/config` («Push when Claude decides», «Push when actions required»);
- никаких входящих портов: «makes outbound HTTPS requests only and never opens inbound ports on your machine».

**Это прямой ответ на жалобу «с телефона старые долгие чаты не видны».** Приложение Claude показывает облачные сессии и **активные** Remote Control сессии; локальная история `claude --resume` с телефона не видна вообще ([mobile](https://code.claude.com/docs/en/mobile)). На ноуте, который засыпает, сессия отваливается — и в списке её нет. На сервере сессия живёт круглосуточно и всегда в списке. Ноутбук с 8 ГБ был причиной не только нехватки памяти, но и этой невидимости.

### Как выглядит рабочий день

Утро, ноут (или телефон):
1. `ssh vault` → попадаешь в tmux, где уже висят сессии-роли: ГД, лиды направлений, стек. Ничего перезапускать не надо — они не умирали с вечера.
2. Работаешь в терминале как сейчас. Разница только в том, что `claude` запущен не на маке.

Отошёл от стола: открываешь приложение Claude → таб **Code** → сессия в списке (иконка компьютера с зелёной точкой) → пишешь с телефона в ту же сессию. Долгая задача закончилась — прилетел push.

Ночная автономная работа: та же схема, что сейчас (`autonomous-feature`), только сервер не спит и не теряет сеть, и SSH к проду идёт с сервера, а не с ноута.

Многосессионность — не костыль, а штатный режим. `claude remote-control` в server mode держит **до 32 параллельных сессий** одним процессом (`--capacity`, по умолчанию 32), и `--spawn worktree` выдаёт каждой сессии свой git-worktree. Это буквально описание твоей схемы «лид + воркеры в worktree», только управляемое с телефона.

### Что нужно сделать один раз

1. **Взять VPS в поддерживаемой стране** (Германия / Нидерланды / Финляндия / Казахстан — см. таблицу провайдеров). Не в РФ.
2. Пользователь не root, ключевая аутентификация SSH, firewall: наружу открыт только 22 (Remote Control входящих портов не требует), fail2ban.
3. `curl -fsSL https://claude.ai/install.sh | bash` — нативный установщик, Node.js больше не требуется ([overview](https://code.claude.com/docs/en/overview)).
4. **Логин.** Запускаешь `claude`, он даёт URL; открываешь на маке, логинишься, браузер показывает код — вставляешь в терминал. Документация про это прямо говорит: «If your browser shows a login code instead of redirecting back… This happens when the browser can't reach Claude Code's local callback server, which is common in WSL2, SSH sessions, and containers» ([authentication](https://code.claude.com/docs/en/authentication)). **Не использовать `claude setup-token`**: такой токен «can only make model requests, so it can't establish Remote Control sessions» — то есть убивает главную фичу переноса.
5. Перенести стек: `~/.claude` (хуки, агенты, скиллы, CLAUDE.md), `~/claude-stack`, `~/tacticum-vault`, `~/stack-vault`, репозитории. Личные репо просто клонируются с GitHub, vault — тоже (они у тебя в личных репозиториях).
6. Секреты: на маке они в Keychain, на Linux Keychain нет. Нужен свой ход — `pass`/`gopass` на GPG или `age`-шифрованный файл, и переписать `~/.claude/hooks/secret.sh` под него. **Это отдельная задача, и её нельзя сделать «по дороге»** — от `secret.sh` зависит вся карта доступов.
7. tmux с автозапуском: systemd-юнит на пользователя, `tmux new-session -d`, плюс `set -g mouse on` и понятные имена окон под роли. Zellij удобнее из коробки (мышь, панели, статус-бар), но tmux уже стоит в любой системе и меньше сюрпризов.
8. Оставить на маке рабочую копию vault как read-only аварийный доступ (см. «сервер недоступен»).

### Долгие команды (это был отдельный критерий)

Всё длинное убирается в алиасы один раз:
```
alias v='ssh -t vault "tmux -CC attach || tmux new"'   # одна буква — и ты внутри
alias rc='claude remote-control --spawn worktree --name'
```
`ssh -t ... tmux -CC attach` (в iTerm2) даёт нативные вкладки iTerm вместо tmux-биндингов. Плюс `ServerAliveInterval 30` и `ControlMaster auto` в `~/.ssh/config`.

Дополнительно: **Telegram-канал** ([channels](https://code.claude.com/docs/en/channels), research preview) — плагин `/plugin install telegram@claude-plugins-official`, и дальше пишешь боту в Телеграм, а работа идёт на сервере в уже открытой сессии. Это самый низкотрудный мобильный путь: не надо открывать приложение и искать сессию. Ограничение: события приходят только пока сессия открыта, а ответ Claude виден в Телеграме, а не в терминале.

## Требования к серверу под ЭТУ нагрузку

Не «рекомендуется 8 ГБ», а по слагаемым. Что именно ест память:

**1. Сам процесс Claude Code — главный едок.** ~150–200 МБ на холостом ходу, 300–500 МБ на сессию по мере набора контекста, и рост примерно на 500 МБ в час активной работы; после ~3 часов RSS доходит до ~4 ГБ ([разбор Marcelo Retana](https://marceloretana.com/blog/why-claude-code-eats-all-your-ram), 2026). Есть открытые баги с утечками до 18–129 ГБ ([#33735](https://github.com/anthropics/claude-code/issues/33735), [#22188](https://github.com/anthropics/claude-code/issues/22188), [#4953](https://github.com/anthropics/claude-code/issues/4953)) — это хвост распределения, но планировать надо с запасом и с ограничителями.

**2. MCP-серверы умножаются на число сессий.** Это ключевой факт для твоей схемы, и он зафиксирован в баге [#45880](https://github.com/anthropics/claude-code/issues/45880): «With N sessions and M configured MCP servers, the system spawns up to N×M node processes with no memory cap». В том же отчёте: 15 сессий × 34 MCP-сервера на 64-гиговом MacBook Pro дважды за вечер уронили машину в kernel panic. У тебя 4 MCP × 4 роли = 16 процессов; при воркерах — больше.

**3. Serena — самый тяжёлый из четырёх.** Она поднимает языковые серверы под каждый проект, и есть открытый (с 2026-01-16, не закрыт) отчёт о съедании ~30 ГБ RAM с невозвратом до убийства процесса ([oraios/serena#944](https://github.com/oraios/serena/issues/944)); в обзорах упоминается и кластер утечки процессов — 90 осиротевших JVM на 21 ГБ. Индексация 30 репозиториев — это ещё и диск, и разовые пики CPU.

**4. Всё остальное** — git-операции по 50 worktree, `rg` по большим деревьям, тесты проекта. Пики, не база.

**Итог по размеру:**

| Ресурс | Минимум | Комфорт | Почему |
|---|---|---|---|
| RAM | 16 ГБ | **24–32 ГБ** | 4 сессии-роли × (0.5–4 ГБ) + 16 MCP-процессов + Serena с языковыми серверами. 16 ГБ работают, но упираются в длинных сессиях — то есть ровно в том режиме, из-за которого затевался переезд |
| vCPU | 4 | **8** | языковые серверы и индексация — CPU-bound пиками; сами сессии в основном ждут сеть |
| Диск | 100 ГБ | **200–300 ГБ** | 30 репо + 50 worktree + кэши Serena + node_modules/venv + логи |
| Swap | — | **8–16 ГБ** | страховка от утечек: лучше свопить, чем ловить OOM-killer посреди ночной работы |

**Ограничители, которые надо поставить сразу** (иначе одна утечка сносит все роли): `NODE_OPTIONS=--max-old-space-size=…` под каждую сессию (рекомендация из [azlin#150](https://github.com/rysweet/azlin/issues/150)) и `MemoryMax=` в systemd-юните на каждую tmux-роль, чтобы OOM убивал одну сессию, а не машину.

Для сравнения: облачная VM Anthropic даёт **4 vCPU / 16 ГБ / 30 ГБ** и сама пишет, что при выходе за эти лимиты надо «use Remote Control to run Claude Code on your own hardware» ([cloud-environments](https://code.claude.com/docs/en/cloud-environments)). 30 ГБ диска на 30 репозиториев с индексами — мимо.

## Что ломается и чего это стоит

**1. Доступ к API из РФ — главный риск, а не деталь.** РФ нет в списке поддерживаемых стран, и Anthropic активно ищет и блокирует доступ через VPN: сообщается о массовых блокировках российских аккаунтов с потерей проектов и истории ([Visegrád 24, 2026](https://x.com/visegrad24/status/2052706261813154263), [ABAB News](https://www.ababnews.com/news/9051a4a7-77ce-4b02-8da8-95a620c60285) — оба вторичные источники, первичного подтверждения от Anthropic я не нашёл, помечаю как **не подтверждено официально**). Что из этого следует практически:
- сервер в поддерживаемой стране — это **улучшение** ситуации, а не обход: у сессии стабильный IP в разрешённой стране, а не пляшущий VPN-выход;
- но приложение Claude и claude.ai **на телефоне** остаются в РФ-сети, и мобильный доступ по-прежнему упирается в тот же барьер. Перенос на сервер эту часть не лечит;
- прокси на сервере ставить нельзя: «Remote Control is also disabled when `ANTHROPIC_BASE_URL` points at a host other than `api.anthropic.com`» ([remote-control](https://code.claude.com/docs/en/remote-control)). Прокси = минус мобильный доступ, то есть минус половина смысла переезда;
- риск блокировки аккаунта — фактор, который надо держать в голове при выборе схемы, а не узнавать после потери истории.

**2. SSH-ключи к прод-серверам.** Сейчас они на маке. После переезда либо ключи ложатся на VPS — и тогда одна машина в интернете держит и агента с шеллом, и доступ к проду; либо `ForwardAgent` с мака — и тогда ночная автономная работа без тебя не имеет доступа к проду. **Развилка, которую надо решить осознанно, а не по умолчанию.** Мой ход: отдельный ключ, выписанный именно для сервера (чтобы ротировать независимо от мака), `command=`/`from=` ограничения в `authorized_keys` на прод-стороне, и на VPS — ключ с парольной фразой в `ssh-agent`, который ты разблокируешь при первом входе за день.

**3. Права агента на машине с ключами.** `--dangerously-skip-permissions` на такой машине — плохая идея, а без него ночная работа встаёт на промптах. Штатный выход из документации по каналам: канал с capability «permission relay» пересылает промпт на телефон, и ты жмёшь «ок» из Телеграма ([channels](https://code.claude.com/docs/en/channels)). Это дороже в настройке, но не требует снимать тормоза.

**4. Синхронизация vault.** Двусторонний sync (Syncthing/rsync) между маком и сервером **не делать**: у тебя vault — это git + база basic-memory, и параллельная правка с двух машин даёт конфликты в обоих слоях сразу. Правильно: **сервер — единственный источник истины**, мак читает через SSH. Бэкап — как сейчас, `git push` в личные репо, плюс снапшоты провайдера.

**5. Сервер недоступен.** Сейчас отказ ноута = отказ всего, и после переезда это не меняется, только точка отказа переезжает. Что реально помогает: клон vault и `claude-stack` на маке (read-only, обновляется `git pull`) — тогда при падении сервера ты хотя бы видишь состояние, доску и регламенты. Полноценно работать не сможешь: MCP, хуки, репозитории и память будут на сервере.

**6. Логин истекает.** Claude Code предупреждает за 3 дня (`Your login expires in 3 days · run /login to renew`), и документация отдельно отмечает: «a Remote Control session that outlives the login stops making progress once the credential expires» ([authentication](https://code.claude.com/docs/en/authentication)). Для сервера, который работает без тебя, это регулярное дежурное действие, а не мелочь.

**7. Обрыв сети у самого сервера.** Remote Control умирает, если машина не видит сеть дольше ~10 минут: «the session times out and the process exits». У VPS это почти никогда — и это как раз аргумент за сервер против ноута, который спит и переключает Wi-Fi.

**8. SSH-разрыв.** Без tmux/screen сессия умирает: «If you close the terminal… the session ends. To keep a session running on a remote machine after you disconnect from SSH, start it inside `tmux` or `screen`» ([remote-control](https://code.claude.com/docs/en/remote-control)). tmux тут не удобство, а обязательный элемент.

**9. Мобильный SSH — только как аварийный путь.** Обычный SSH по TCP умирает при засыпании телефона и смене сети; выживает mosh. Blink Shell — самая обкатанная реализация mosh на iOS, Termius тоже умеет mosh (включая бесплатный тариф), но держит долгие сессии на background keep-alive и жрёт батарею ([TermAI, 2026](https://termai.sh/blog/blink-shell-vs-termius), [docs.blink.sh](https://docs.blink.sh/advanced/advanced-mosh)). Но **основной мобильный путь — не SSH-клиент, а приложение Claude через Remote Control**: набирать промпты в терминале с телефона мучительно, а в приложении это нормальный чат с push-уведомлениями.

## Чего делать НЕ надо и почему

**Не переезжать в Claude Code on the web как в основной дом.** Документация перечисляет, что **не** доезжает до облачной сессии ([cloud-environments](https://code.claude.com/docs/en/cloud-environments)): пользовательский `~/.claude/CLAUDE.md` — нет; `~/.claude/skills/`, `~/.claude/agents/`, `~/.claude/commands/` — нет; MCP-серверы, добавленные в local/user скоупе, — нет; статические токены и креденшлы — нет («No dedicated secrets store exists yet»); настройки, доставленные на устройство через MDM/managed settings, — нет. Доезжает только то, что закоммичено **в репозиторий**. Твой стек — весь пользовательского уровня: 30 хуков в `~/.claude/hooks`, компания ролей, четыре дома памяти. Плюс: одна сессия = один репозиторий, обязателен GitHub, шелла в VM у тебя нет («You don't get a shell into the session VM»), сеть — доменный allowlist, значит SSH к прод-серверам оттуда невозможен в принципе. Это не «неудобно» — это другой инструмент под другую задачу.

**Не ставить сервер в РФ** (Selectel, Yandex Cloud, российские локации Timeweb). Причина не в качестве хостинга — оно хорошее — а в том, что `api.anthropic.com` из РФ недоступен, а единственный способ это обойти (`ANTHROPIC_BASE_URL` на прокси) документированно выключает Remote Control, то есть весь мобильный доступ.

**Не брать 8 ГБ VPS.** Это перенос проблемы, а не решение: считай по слагаемым из раздела о требованиях — 4 роли и 16 MCP-процессов в 8 ГБ не живут, а Serena может одна съесть больше.

**Не заводить двусторонний sync vault.** Конфликты в git и в базе basic-memory одновременно — самая дорогая по времени поломка из всех перечисленных, и чинить её придётся руками в двух слоях.

**Не использовать `claude setup-token` / `CLAUDE_CODE_OAUTH_TOKEN` на сервере.** Соблазн понятный: логин без браузера. Цена: такой токен не умеет поднимать Remote Control сессии — то есть ты одной строкой отключаешь то, ради чего переезжаешь.

**Не делать code-server / VS Code Remote основным способом работы.** Как дополнение для чтения диффов — хорошо. Как основа — нет: это редактор, а твоя работа идёт в терминальном агенте, и лишний слой (веб-IDE в браузере) добавляет память на сервере, латентность и точку отказа, не решая ни одной из твоих проблем. Мобильный доступ он тоже не решает.

**Не гнаться за гибридом «MCP на сервере, сессия локально».** Serena умеет SSE и её действительно можно унести, но `basic-memory` работает по файлам vault, а главный едок памяти — сами процессы Claude Code, которые в этой схеме остаются на маке. Получишь сложную топологию и половину выигрыша.

**Не включать `--dangerously-skip-permissions` на машине, где лежат ключи к проду.** Это единственная машина, где такое решение необратимо: агент с шеллом, ключами и без тормозов на хосте, доступном из интернета.

## Открытые вопросы (ждёт проверки, не выдумывать)

1. Точные цены Timeweb Cloud на 16/32 ГБ и наценка за зарубежные локации — публичная страница их не показывает, смотреть в панели.
2. Принимает ли Contabo оплату из РФ — в терминах есть sanctions-screening, практика неизвестна.
3. Aeza: конфигурации и оплата — страницы тарифов недоступны для внешнего запроса.
4. Vultr / OVH / Scaleway не проверены (403 и нехватка времени) — резерв, если первые два варианта не пройдут по оплате.
5. Латентность из точки, где ты находишься, до Амстердама/Франкфурта — измерить `mtr` перед покупкой; для SSH важна не полоса, а джиттер.
