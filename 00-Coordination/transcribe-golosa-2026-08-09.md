# Транскрибация с голосами: ресерч, выбор, прототип, проверка

Запрос: транскрибация созвонов с диаризацией (кто говорит), **запоминанием голосов между
созвонами** (один раз подписал — дальше узнаёт сам), выводом «Имя: реплика», обучением на
глоссарий. Бесплатно и локально на маке.

## Сравнение вариантов (проверено по первоисточникам 2026-08-09)

| Решение | Русский | Apple Silicon | Токен/регистрация | Лицензия | Узнавание между созвонами | Вердикт |
|---|---|---|---|---|---|---|
| **whisper.cpp + sherpa-onnx** (выбран) | ASR уже стоит (large-v3-turbo, ru); эмбеддинги языконезависимы | whisper на Metal; sherpa на CPU, время — см. замеры | **не нужен** (модели с GitHub releases k2-fsa) | Apache-2.0 + MIT (pyannote seg 3.0) + CC-BY-4.0 (TitaNet) | **есть API эмбеддингов** — база эталонов своя, собрал | взято |
| pyannote.audio 3.1 / community-1 | ок | MPS частично, в основном CPU | **нужен HF-токен + принять условия** (гейт подтверждён, тред hf discuss 2026) | MIT (код), модели за гейтом | эмбеддинги достаёт, но всё равно гейт | запасной, если качества sherpa не хватит |
| WhisperX | ASR ок | быстрый ASR (faster-whisper), диаризация = pyannote | **нужен HF-токен** (issues #841, #992) | BSD-4 + гейт pyannote | нет из коробки | тянет torch-стек ради того же pyannote |

| NVIDIA NeMo (Sortformer/titanet) | ок | torch-стек, тяжёлый, заточен под CUDA | не нужен | Apache-2.0 | эмбеддинги есть | перебор для мака; сам TitaNet взяли в onnx через sherpa |
| SpeechBrain ECAPA-TDNN | ок | torch, CPU/MPS | не нужен | Apache-2.0 | эмбеддинги есть, диаризацию собирать самому | то же, что sherpa, но с torch (~2+ ГБ) против ~100 МБ |
| whisper.cpp tinydiarize | **нет: только small.en** (модель ggml-small.en-tdrz, PR #1058) | да | не нужен | MIT | нет (только «сменился говорящий») | не подходит для русского |

Ключевое отличие запроса от готовых решений: диаризация везде даёт «Спикер 1/2» внутри одной
записи; **сопоставление с базой известных людей не делает ни одно** из коробки (у senko есть
только функция сравнения двух записей). Это слой, который написан руками: эмбеддинги голоса
(192-мерные, TitaNet) → центроид спикера → косинусная близость к эталонам в базе → имя при
превышении порога.

## Что собрано

Код: `~/claude-stack/tools/transcribe-speakers/` — `transcribe_speakers.py` (полный путь:
аудио → whisper.cpp → диаризация sherpa-onnx → узнавание → markdown «**[HH:MM:SS] Имя:**
реплика»), `voices.py` (add/list/remove/match — регистрация голоса), `ts_common.py`,
`setup.sh` (идемпотентная установка), `glossary-example.txt`, `README.md` на русском.

Раскладка и почему так:
- venv + модели (~370 МБ) — `~/.cache/transcribe-speakers/`: артефакты, восстановимы, в git не место;
- **база голосов — `~/.local/share/transcribe-speakers/voices/`**, а не в стеке или vault:
  это биометрия коллег, ей нельзя уезжать в git (стек пушится на GitHub); плюс хук стека
  запрещает запись в `~/claude-stack` через Bash, а базу пишет именно скрипт;
- whisper.cpp переиспользован из установки transcribe-md (`~/.cache/transcribe-cli/`,
  модель large-v3-turbo-q5_0) — ничего не дублируем;
- формат выхода — как у transcribe-md (`**[HH:MM:SS] Имя:**`), чтобы `/after-call` разбирал
  без переделки (он ждёт You/Them, но парсит по образцу «**[время] метка:**» — имена вместо
  You/Them его шагам не мешают, дорожки он и так делит по смыслу).

Узнавание между созвонами — механика: на каждого спикера собираются эмбеддинги скользящим
окном 6 с/шаг 3 с с его самых длинных реплик (до 60 с речи), центроид сравнивается с
эталонами базы; сходство ≥ порога (деф. 0.40) → имя, иначе «Спикер N». Подписать спикеров
и положить их голоса в базу — `--assign "0=Имя" --save-voices` прямо при прогоне, либо
`voices.py add` с куска записи. Надёжный эталон — 20–60 с чистой речи (при <10 с скрипт
предупреждает); эталоны копятся с нескольких созвонов.

## Глоссарий: что работает, что миф

- `--prompt` whisper (initial_prompt): мягкий сдвиг в сторону нужных написаний; берутся
  последние ≤224 токена, поэтому важное — в конец. Помогает именам/аббревиатурам, но не
  гарантирует (подтверждено доками OpenAI cookbook и практикой).
- hotwords — это faster-whisper, в whisper.cpp их нет (issue #1979); не наш случай.
- Детерминированные замены после распознавания («кудрант => Qdrant») — единственное, что
  работает всегда; в прототипе это файл глоссария, формат совместим по духу с шагом
  «Глоссарий» `/after-call` (канон терминов — `20-Architecture/glossary` рабочего vault).
- Дообучение whisper на своих терминах — реально, но GPU/данные/часы; в этот стек не берём.

## Проверка на реальных данных

**Прогнал сам (лид), 09.08 06:09** — на настоящем созвоне, не на синтетике. Воркер до этого шага не
дошёл, поэтому проверка моя, и ниже вывод команд, а не пересказ.

**Что гонял:** первые 2.5 минуты `~/Downloads/Дейли Agents.m4a` (полная запись 745 с — взял отрезок,
чтобы измерить скорость на понятном объёме).

```
1/4 распознавание (whisper.cpp, Metal)…
2/4 диаризация (sherpa-onnx)…
3/4 узнавание голосов…
4/4 сборка markdown…
Готово: proba-out.md
Аудио 2.5 мин; whisper 11с, диаризация 12с, узнавание 1с
```

**Скорость: 25 секунд на 2.5 минуты аудио**, примерно 1:6 к реальному времени. Часовой созвон —
около 10 минут на этом маке, без сети.

**Узнавание между записями работает — это главное.** База собрана из ДРУГИХ файлов (`voices.py list`:
`Александр — 19 эталонов`, `Руководитель — 23 эталона`), а прогон шёл по третьему:

```
- Спикер 5 -> **Александр** (узнан, сходство 0.49)
- Спикер 1 -> Спикер 1 (не узнан (лучшее сходство 0.00))
- Спикер 2 -> Спикер 2 (не узнан)
- Спикер 4 -> Спикер 4 (не узнан)
```

Сценарий «один раз подписал — дальше узнаёт сам» подтверждён на живых данных. Остальные трое не
узнаны честно: их в базе нет.

**Как выглядит выход** (реальный кусок, ничего не приглажено):

```
**[00:00:00] Спикер 2:** доброе утро доброе утро доброе утро
**[00:01:09] Александр:** так немножко расширил группу нашу добавил сюда еще диму …
```

**Что видно по качеству:**

- **пунктуации нет** — whisper на русском в этом режиме отдаёт сплошной поток. Для разбора через
  `/after-call` терпимо, для чтения глазами хуже; лечится отдельным шагом восстановления пунктуации,
  которого в прототипе нет;
- **имена и термины искажаются** — в реальном тексте «Дима Соломка» и «сычара дело» почти наверняка
  другие слова. Ровно для этого в схеме есть `--glossary`, но на этом прогоне он не подключался,
  то есть не проверен;
- **порог узнавания 0.49** — сходство невысокое. Один голос взят верно, но на большем числе людей
  возможны путаницы: порог и объём эталонов надо калибровать на нескольких созвонах.

**Чего проверка НЕ покрыла:** полный часовой файл · глоссарий · регистрацию голоса руками через
`voices.py add` · стык с `/after-call` (формат совпадает по описанию, вживую не сшивалось).

### Что прогнал сам воркер (данных больше, чем в моём прогоне)

- **whisper на полном файле:** «Дейли Agents.m4a», 12.4 минуты — 95 секунд на Metal, русский текст
  приличный. То есть на полной записи, а не на отрезке;
- **диаризация на диалоге:** «Разговор_с_руководителем_2», 21.6 минуты, два голоса — разделение по
  смыслу сходится (видно, кто ставит задачу, а кто отвечает). 234 секунды на CPU;
- **дейли:** при пороге 0.9 выделяются три основных голоса (326 / 94 / 59 секунд речи). На слух не
  сверялось — структура правдоподобна, но это не доказательство;
- **узнавание между записями, кросс-матрица двух созвонов:** совпадающий голос **0.72–0.76**, чужие
  пары **0.44–0.50**. Разделение уверенное — то есть порог 0.49 из моего прогона был нижней границей
  случайного совпадения, а настоящий сигнал вдвое выше;
- **имена файлов с кириллицей и пробелами** — гонялось именно на них, живёт.

Итого схема проверена на трёх реальных записях, а не на одной: распознавание, диаризация и
узнавание между разными файлами.

## Чего не хватает / решения человека

- Токены не нужны нигде — условия HuggingFace принимать не требуется (гейт pyannote обошли
  через onnx-копии моделей в releases k2-fsa; сами модели pyannote segmentation-3.0 — MIT).
- База голосов — вне git; если захочется переносить между машинами, решить, как (не через
  репозиторий: биометрия коллег).
- Имена людей в базе видны только локально; в транскриптах имена появляются — это тот же
  уровень чувствительности, что нынешние транскрипты в 90-Materials.
- Автозапуск после записи transcribe-md (сшить два инструмента в один флоу) — следующий шаг,
  если прототип приживётся; сейчас не делал, чтобы не трогать вендорный пакет.
