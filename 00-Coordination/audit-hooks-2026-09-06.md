# Аудит хуков и гейтов 06.09.2026

Скоуп: `~/.claude/hooks/*.sh` (36 скриптов) и `~/.claude/settings.json`. Метод: чтение кода +
запуск read-only команд и хуков с тестовым входом. Дефекты, уже записанные в
`40-Debt/tech-debt.md`, сюда не включены (сверено по всему файлу: dossier-archive в контуре
стека, вечно-красная диагностика, ITERM-легаси, кнопки-стопа-где-угодно, догоняющий гейт и т.д.).

Каждый пункт: **файл:строка · что не так · чем доказано · починка одной строкой.**
Порядок — по опасности.

## 1. 🔴 grant-write: барьер «запись открывает только человек» не существует механически

**`grant-write.sh:8-9`.** Шапка утверждает: «Агент сам себе её открыть не может — этот скрипт
правит `.ssh-manager/.env`, а запись в периметр через Bash агенту закрыта гейтом. То есть команду
он может только ПРЕДЛОЖИТЬ».

**Что не так.** `~/.ssh-manager/.env` в периметре гейта НЕ находится. Перечень часовых SENTINEL
(`guard.sh:2002-2003`) — `agent-stack.conf`, `.role-registry`, `.claude/settings*.json`,
`.claude/hooks`, `.claude/agents`. Ни `.ssh-manager`, ни `grant-write` в guard.sh не упоминаются
ни разу.

**Чем доказано.** `grep -n 'ssh-manager/\.env\|\.ssh-manager\|grant-write' guard.sh` → 0 строк
(совпадения только по MCP-инструментам `mcp__ssh-manager__*`). То есть
`bash ~/.claude/hooks/grant-write.sh <сервер> 30` из Bash гейт не остановит; рабочие роли с 09.08
работают в `bypassPermissions`, значит и слой разрешений это не спросит. Прямая правка
`sed -i` по `~/.ssh-manager/.env` — тоже вне периметра CONFIG/A2.

**Почему это верх списка.** Это механизм readonly-серверов, придуманный Президентом 16.08
(«агент должен мне скинуть команду, которую я впишу»). Норма чтит его дисциплиной, а её опора
(«закрыто гейтом») — прямая ложь в тексте скрипта; ровно класс «норма описывает механизм,
которого нет».

**Починка:** добавить `\.ssh-manager\b|grant-write\.sh` в регулярку `SENT` (guard.sh:2002) —
либо переписать шапку честно: «держится дисциплиной, гейт этот файл не охраняет».

## 2. 🔴 stop-reminder велит вооружать монитор, отменённый 23.08

**`stop-reminder.sh:100-104`.** Текст напоминания, который хук возвращает роли, заканчивается:
«Если монитор канала не вооружён, поставь его…» + готовый сниппет
`Monitor({command: "…signal-watch.sh <роль>", persistent: true…})`.

**Что не так.** Мониторы канала отменены 23.08.2026 (`~/claude-stack/signals.md`, раздел «Как
принять — монитор больше НЕ вооружается»): будит нативная доставка, а монитор породил класс
«монитор-сирота, вычерпывающий inbox в никуда» и «два монитора на адрес — дубли в оба окна».
`signal-status.sh:91-99` ту же подсказку удалил у себя именно с этой формулировкой («подсказка,
предлагающая починить то, чего по замыслу больше нет»), а stop-reminder — нет. Каждый раз, когда
страховка срабатывает, она воспроизводит убитый класс отказов: послушная роль поднимет монитор,
и он у неё переживёт сессию сиротой.

**Чем доказано.** Чтение обоих файлов + канон signals.md (строки 150-224).

**Починка:** заменить хвост reason (строки 102-104) на «очередь разбирается при подъёме окна:
`bash ~/.claude/hooks/signal-status.sh`», сниппет Monitor убрать.

## 3. 🔴 Проверка доктора «сигнал висит у работающей роли» слепа по построению

**`stack-doctor.sh:411`.** Условие «роль работает» — `pgrep -f "signal-watch\.sh ${r}\$"`.
Монитор не поднимает никто с 23.08, значит pgrep пуст всегда, и варн «у РАБОТАЮЩЕЙ роли to:X
сигнал висит >12 ч» не может сработать никогда. Это тот же корень, который 06.09 уже починили в
`stuck-check.sh:46-49` («прежний признак pgrep signal-watch ослеп ПО ПОСТРОЕНИЮ 23.08… LIVE был
вечно пуст») — но копию в докторе разведка не тронула. Доктор обещает детекцию, которой нет:
класс «гейт, который врёт».

**Чем доказано.** Чтение stack-doctor.sh:398-413 рядом с stuck-check.sh:46-63; `pgrep -f
signal-watch` на живой машине пуст.

**Починка:** живость роли брать из `~/.claude/.role-registry` по pid (готовый код — в
stuck-check.sh:51-63), pgrep оставить только проверке «остался запущенный монитор — погаси».

## 4. 🟠 gate-check: код возврата 0 при невыполненных проверках в нестрогом режиме

**`gate-check.sh` (хвост).** Контракт в комментарии: «0 — нарушений нет И всё, что просили,
проверено; 3 — нарушений нет, но часть проверок не выполнена». Код:
`ok_overall = passed and (not blocking or not strict)` → без `GATE_STRICT=1` при непустом
`blocking` возвращается **0**, а не 3. Персона стека прямо учит «помни, что код 3 это „часть
проверок не выполнена“, а не „чисто“» — но увидеть 3 вызывающий может только в строгом режиме;
в обычном тот же случай приходит нулём, и скрипт-обёртка, смотрящий на rc, считает «чисто».

**Чем доказано.** Чтение финального блока (`raise SystemExit(0 if ok_overall else (1 if not
passed else 3))`) — при strict=0, passed=1, blocking≠∅: ok_overall=True → rc 0.

**Починка:** `raise SystemExit(0 if (passed and not blocking) else (1 if not passed else 3))` —
rc 3 всегда при непроверенном; GATE_STRICT пусть решает только, блокировать ли 3 в пайплайне.

## 5. 🟠 session-start рекомендует погашенные команды и проверяет несуществующий артефакт

**`session-start.sh:67-70, 126, 130`.** Баннер: «/morning сегодня не запускался → /morning или
/catchup» и «чекпойнт устарел → /wrap». Обе команды погашены 23.08 (заглушки: «заменена на
/grid» / «заменена на /working-end»). Хуже: признак «/morning был» — файл
`31 — Сессии/daily-<дата>.md`, а `/grid` таких файлов не создаёт (grep по grid.md — 0 упоминаний
`daily-`; в живой папке `31 — Сессии` нет ни одного daily-*.md). То есть строка «не запускался»
горит ВСЕГДА и рекомендует мёртвую команду — вечно-красная диагностика.

**Чем доказано.** Чтение commands/morning.md, wrap.md (заглушки), grep grid.md, ls живой папки.

**Починка:** признак дня взять из артефакта /grid, текст → «→ /grid или /catchup», «/wrap» →
«/checkpoint» (для чекпойнта) и «/working-end» (для конца дня).

## 6. 🟠 Хардкод «30 — Координация» в четырёх скриптах — половина канала мертва в контуре стека

Пять скриптов ищут папку координации перебором трёх имён (`signal-send.sh:26-29`,
`signal-status.sh:21-24`, `signal-watch.sh:66-70`, `board-sweep.sh:54-56` — с комментарием
«рабочий vault переехал 23.08, контур стека остался на `00-Coordination`, скрипт общий»), а
четыре — хардкодят русское имя:

- **`stop-reminder.sh:66`** — inbox только `30 — Координация` → страховка сигналов молча не
  работает ни в одном vault без русского имени (в т.ч. stack-vault);
- **`stuck-check.sh:64, 111, 138`** — все три признака застревания;
- **`worker-log.sh:23-25`** — `[ -d …/30 — Координация ] || exit 0`: в контуре стека журнал
  воркеров не пишется вовсе (SubagentStart/Stop выходят молча), и признак №2 stuck-check там
  слеп заодно;
- `waiting-queue.sh:38` — вероятно намеренно (очередь Президента — про рабочую доску), но тогда
  это стоит сказать в шапке.

**Чем доказано.** grep по всем девяти скриптам (вывод в ходе аудита); `ls
~/stack-vault/00-Coordination/signals` — папки нет, т.е. сегодня канал в контуре стека не
используется, дефект спящий — но проявится молча в первый же день использования.

**Починка:** вынести перебор трёх имён в общую функцию (или в `agent-stack.conf` переменной
`AGENT_COORD_DIR`) и использовать во всех девяти.

## 9. 🟡 voice-response: утечка temp-файлов и вечный лок при жёсткой смерти

**`voice-response.sh:51`.** `out="$(mktemp /tmp/claude-voice-XXXX).mp3"` — mktemp СОЗДАЁТ файл
`/tmp/claude-voice-XXXX`, а удаляется потом только `$out` (с суффиксом .mp3). Пустышка от mktemp
остаётся навсегда — по файлу на каждую озвучку. Плюс `mkdir /tmp/claude-voice.lock` (строка 49):
если фоновый процесс убит до trap (закрыли терминал), лок живёт до перезагрузки и голос молча
выключен — «занято — молчим».

**Чем доказано.** Чтение кода; поведение mktemp — документированное.

**Починка:** `out="$(mktemp /tmp/claude-voice-XXXXXX.mp3 2>/dev/null || mktemp
/tmp/claude-voice-XXXXXX)"` (одним файлом) + в проверке лока снимать каталог старше ~5 мин, как
это делают role-register/session-end.

  тогда строчку в HANDBOOK.
- **`~/claude-stack/tools/srv-team.sh:4,11,32,194`** (смежное, вне скоупа хуков) — комментарии

## Побочный эффект аудита (устранён)

При прогоне пустого входа был запущен `session-end.sh` — он штатно закоммитил висевшие изменения
stack-vault (локальный коммит e6fc228 «авто-коммит памяти…») и снял из `.role-registry` строку
живой сессии stack. Строка восстановлена (`role-register.sh stack`, pid 14061 сверен с живым
процессом claude). Заодно вскрылось свойство: ручной запуск session-end.sh при живой сессии
дерегистрирует её, потому что sid берётся из окружения — хук рассчитан только на настоящий
SessionEnd.
