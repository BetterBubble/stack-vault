# Интерфейсы вместо терминала: сайт/приложение для компании агентов

**Сценарий:** ГД + 3–5 лидов, каждый в своей tmux-сессии на удалённом Linux-сервере, плюс локальные сессии на маке. Нужно: видеть все сессии, переключаться, писать им, красиво/стабильно из коробки, переживать обрывы SSH, минимум ручной возни.
**Продолжение** ресерча терминалов ([[research-terminal-2026-09-06]]). Дата: 2026-09-06, всё проверено веб-поиском по состоянию на сентябрь 2026.

---

## 1. Официальное от Anthropic — тут случился прорыв, которого не было год назад

### 1.1 Remote Control — главная находка ресерча

**Что это.** Официальная фича Claude Code (запущена в феврале 2026 как research preview, сейчас доступна на всех планах): сессия CLI **регистрируется на claude.ai/code и в мобильном приложении Claude**, и ей можно управлять из браузера/с телефона. Claude продолжает работать там, где запущен CLI — исполнение, файлы, MCP, хуки остаются на той машине. Веб и телефон — «окно» в живую сессию ([доки Remote Control](https://code.claude.com/docs/en/remote-control), [анонс Boris Cherny](https://x.com/bcherny/status/2038454339933548804)).

**Почему это закрывает ровно наш сценарий:**
- **Работает на удалённом сервере.** Доки прямо говорят: чтобы сессия на удалённой машине жила после отключения SSH — запускать её **внутри tmux** (наш сетап дословно). CLI на сервере делает только исходящие HTTPS-запросы, никаких входящих портов.
- **Список всех сессий в одном месте.** Каждая сессия с включённым RC появляется в списке на claude.ai/code и в приложении (вкладка Code) с именем (`--name "ГД"`, `--name "Лид-1"`…), зелёной точкой онлайн-статуса. Переключение — клик по сессии. Это и есть «видеть всех и писать любому».
- **Включается на всех сессиях разом:** настройка `remoteControlAtStartup: true` в `~/.claude/settings.json` на сервере — каждый интерактивный процесс регистрирует свою сессию автоматически. Один процесс = одна сессия; наши 4–6 процессов = 4–6 сессий в списке.
- **Переживает обрывы по построению.** Сеть упала / мак уснул → CLI на сервере сам переподключается, сообщения и permission-промпты копятся в очереди и доезжают после восстановления. Обрыв SSH с мака вообще ничего не рвёт — транспорт-то теперь не SSH, а HTTPS до Anthropic.
- **Пуши на телефон:** «Claude ждёт решения», «задача закончилась» — в `/config` два тумблера (Push when Claude decides / when actions required).
- **Картинки и файлы** — прикладываются с телефона/из браузера и доезжают в сессию (решает боль drag&drop из терминального ресерча).
- **Видны сабагенты и workflows** сессии, их можно остановить с телефона. Диффы незакоммиченных изменений показываются в отдельной панели. Модель/effort переключаются с устройства.
- **Cross-session messaging** — сессии на разных машинах могут писать друг другу через тот же канал (v2.1.224+): задел для раздачи задач ГД→лиды.

**Ограничения и цена вопроса (честно):**
- Нужен **логин claude.ai (Pro/Max)**; API-ключ не поддерживается. Не работает с `ANTHROPIC_BASE_URL`/гейтвеями/Bedrock.
- Выставленные `DISABLE_TELEMETRY` / `DO_NOT_TRACK` / `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` **ломают RC** — проверить env на сервере.
- **Транскрипт сессии при активном RC хранится на серверах Anthropic** (для синка устройств). Исполнение и файлы — на нашей машине, но сам диалог уезжает. Для личного стека приемлемо, знать надо.
- Часть команд — только в терминале (`/resume`, `/plugin`); `/model`, `/mcp`, `/config`, `/compact` и пр. работают с веба/телефона. То есть терминал понадобится изредка — тонкая «служебная форточка», не рабочее место.
- Процесс CLI обязан жить → **tmux на сервере остаётся** как супервизор процессов (что и хотели: обвязка переживает миграцию нетронутой).

### 1.2 Teleport — сцепка облака и терминала

`claude --teleport` / `/teleport` — перенос облачной сессии к себе в терминал и обратно; вместе с RC даёт полную переносимость сессий между терминалом/вебом/телефоном ([гайд](https://docs.bswen.com/blog/2026-03-30-claude-code-teleport-remote/), [feature request на полную унификацию — ещё открыт](https://github.com/anthropics/claude-code/issues/32992)). Для нашего сценария вторично: наши сессии живут на своём сервере, а не в облаке Anthropic.

### 1.3 Claude Desktop app (Mac) — «Code» таб

Официальное десктоп-приложение теперь полноценный GUI для Claude Code: параллельные сессии в сайдбаре, изоляция git-worktree на сессию, визуальный дифф-ревью, редактор файлов, side chats, PR-мониторинг — и главное **SSH-сессии**: приложение само ставит Claude Code на удалённую машину и запускает сессии **на нашем сервере**, с permission-модами, MCP и плагинами с сервера ([доки Desktop](https://code.claude.com/docs/en/desktop)).

**Но для полной миграции компании агентов подходит хуже, чем кажется:**
- Desktop видит **только сессии, которые запустил сам** (local/SSH/WSL). Наши tmux-сессии, поднятые обвязкой на сервере, в нём **не появятся** — в отличие от RC, который цепляется к любой CLI-сессии.
- Значит миграция на Desktop = пересборка запуска компании под его модель (сессии создаёт приложение), а не перенос обвязки как есть.
- Переживает ли SSH-сессия Desktop сон мака/обрыв — в доках не сказано; проверить не смог, закладываться нельзя.
- **Dispatch** (Pro/Max, не Team/Enterprise): задача с телефона → приложение само поднимает Code-сессию на маке, пуш по завершении. Приятный бонус для локальных задач, к серверному сценарию не относится.

Роль Desktop у нас: **клиент для просмотра RC-сессий и локальных задач**, не замена серверной обвязке.

### 1.4 Claude Code on the web (claude.ai/code)

Облачные сессии на инфраструктуре Anthropic — репо клонируется к ним, окружение их. Наш сценарий противоположный: сессии на СВОЁМ сервере с СВОИМИ MCP/хуками/памятью. Применим только интерфейс claude.ai/code как окно в RC-сессии (п. 1.1); сами облачные сессии нам не нужны (self-hosted environments — только Team/Enterprise).

## 3. Что реально заменит iTerm2+tmux, а что — надстройка

- **Полной замены «tmux на сервере» нет ни у кого** — и не надо: сам Anthropic рекомендует tmux как супервизор для RC на удалённой машине. Обвязка/хуки/роли переживают всё нетронутыми.
- **Заменяется именно то, на что смотрит и чем тыкает человек:** iTerm2 с пятью вкладками → список сессий на claude.ai/code / в приложении Claude (Mac и iPhone).
- Conductor/Sculptor/claude-squad — не интерфейсы к нашим сессиям, а **другие способы их порождать**: миграция на них = пересборка компании, выигрыша против RC нет.
- Happy — единственная сторонняя вещь, решающая ту же задачу, что RC, и местами лучше (E2E, self-hosted, голос). Но ставить стороннюю обёртку, когда официальная фича делает то же и развивается темпом Anthropic — лишний риск-слой.

## Вердикт

**Топ-вариант полной миграции интерфейса: официальный Remote Control.** Сессии остаются в tmux на сервере (обвязка не трогается), но смотрим на них и пишем им через **claude.ai/code в браузере + приложение Claude на iPhone/Mac**. Красиво из коробки, официально, обрывы SSH перестают быть болью в принципе — транспорт теперь HTTPS с очередями и авто-реконнектом. Терминал остаётся тонкой служебной форточкой (редкие `/resume`, аварийный attach) — сюда хватит Ghostty+mosh из первой части ресерча, но уже без амбиций «рабочего места», т.е. и osascript-раскладку можно не переносить вовсе.

**Путь миграции (обратимый, по шагам):**
1. На сервере проверить: логин claude.ai (Pro/Max), нет `ANTHROPIC_BASE_URL` и `DISABLE_TELEMETRY`-семейства в env.
2. Пилот на одной сессии лида: `claude --remote-control "Лид-1"` внутри её tmux — открыть на claude.ai/code и в приложении, погонять день: пуши, картинки, апрувы с телефона.
3. Понравилось → `remoteControlAtStartup: true` в настройках на сервере (или `--rc` в обвязку запуска) + имена сессий через `CLAUDE_REMOTE_CONTROL_SESSION_NAME_PREFIX`/`--name` — вся компания в одном списке.
4. Пуши: `/config` → Push when actions required (+ when Claude decides по вкусу).
5. iTerm2/Ghostty оставить как служебный вход; mosh — по желанию, критичность упала.
6. Через неделю решить судьбу локальных сессий мака: их тоже в RC (тот же список) и/или Desktop app.

**Осознанный компромисс:** транскрипты RC-сессий лежат на серверах Anthropic. Неприемлемо → план Б: **Happy с self-hosted сервером** (E2E, тот же UX), ценой стороннего слоя. План В: всё из первой части — Ghostty+mosh, интерфейс остаётся терминальным.

**Не проверено вживую:** поведение RC при 5–6 параллельных сессиях с одного аккаунта (лимитов в доках нет, server mode держит 32); совместимость RC с нашими хуками-гейтами на permission-промптах (должны просто форвардиться на телефон — механизм тот же, но не гонял); живость VibeTunnel; переживает ли Desktop-SSH-сессия сон мака.
