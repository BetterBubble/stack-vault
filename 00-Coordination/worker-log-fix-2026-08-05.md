# Журнал воркеров: «STOP ?» — не потерянный START (пункт 6)

## Причина: постановка была неверной, START не терялся

Строки `STOP ?` без парного `START` — это **не воркеры**. Это событие, которое харнес присылает
на **конце хода лида**, когда в сессии есть фоновые агенты. Хук принимал его за финиш воркера и
писал строку `STOP` — то есть сам же и создавал непарные записи, на которых потом ломалась
проверка «START без STOP = воркер повис».

### Доказательство: 15 из 15 строк совпадают с концами хода, минута в минуту

Концы хода видны в транскрипте сессии как записи `system` с `subtype: stop_hook_summary`
(Stop-хук отработал) и `subtype: away_summary` (сводка «пока тебя не было»). Сверка по двум
независимым сессиям — все непарные `STOP` до одной:

| сессия `bcd9aeb3` (05.08) | событие в транскрипте | сессия `f34ac4a3` (30.07) | событие в транскрипте |
|---|---|---|---|
| 21:23 | 21:23:06 stop_hook_summary | 02:14 | 02:14:38 away_summary |
| 21:33 | 21:33:40 stop_hook_summary | 02:37 | 02:37:46 away_summary |
| 21:43 | 21:43:50 stop_hook_summary | 03:20 | 03:20:07 away_summary |
| 21:53 | 21:53:19 stop_hook_summary | 04:26 | 04:26:14 stop_hook_summary |
| 21:58 | 21:57:57 stop_hook_summary | 04:30 | 04:30:36 stop_hook_summary |
| 22:04 | 22:04:07 stop_hook_summary | | |
| 22:14 | 22:14:08 stop_hook_summary | | |
| 22:15 | 22:15:21 stop_hook_summary | | |
| 22:19 | 22:19:53 away_summary | | |
| 22:33 | 22:33:02 stop_hook_summary | | |

Ни одного лишнего, ни одного пропущенного: в сессии `bcd9aeb3` концов хода одиннадцать, непарных
`STOP` — десять, и единственный конец хода без строки (20:15:43) случился **до** появления в
сессии первого субагента. То есть событие приходит именно тогда, когда в сессии есть фоновые
агенты, — и это же объясняет, почему явление выглядело «каждые десять минут».

Три независимых подтверждения того, что это не воркеры:

- **Рядом нет ни одного вызова `Agent`.** Проверены и транскрипт лида, и все транскрипты
  тиммейтов: за час, в котором накопилось десять строк, был ровно один вложенный спавн (в 20:23,
  `claude-code-guide`) — и он записан в журнал **парой** `START`/`STOP` с типом.
- **Этих агентов не существует.** `agent_id` из непарных строк (`a5725454`, `a186f951`,
  `ac7206d7`, …) не встречается в транскриптах нигде, и файла транскрипта
  `…/subagents/agent-<id>.jsonl` для них нет — а у каждого настоящего субагента он есть.
- **Форма payload другая.** Дамп сырых входов хука (включён на время разбора) показал: у
  настоящего `SubagentStop` всегда есть `agent_type` и `agent_transcript_path`; у этих событий нет
  ни того, ни другого — поэтому в журнале и стоял голый `?`.

### Заодно найдены два молчащих дефекта рядом

- **Ротация журнала уничтожила бы шапку.** Формула «шапка = не-дефисные строки среди первых 20,
  тело = все дефисные» ломала файл дважды: элементы `tags:` (`- board`, `- workers`) уезжали в
  тело, а всё, что в шапке стояло после 20-й строки, не попадало ни в шапку, ни в тело и
  исчезало. Не сработало только потому, что журнал ни разу не дорос до 400 строк.
- **Запись не была защищена от гонки.** Пять воркеров стартуют в одну минуту, а ротация читает
  файл целиком и перезаписывает его: строка соседа, попавшая между чтением и записью, исчезала
  без следа. Плюс `STOP` читал журнал ради своего `START` без блокировки.

## Что изменено

Логика — целиком в `~/.claude/hooks/worker-log.sh`; рядом обновлена шапка `_workers.md` и добавлен
прогон `~/claude-stack/tests/test-worker-log.sh`.

1. **Не-воркерские `SubagentStop` в журнал не пишутся.** Признак: нет `agent_type`, нет парного
   `START` в журнале и нет `agent_transcript_path`. Такие события уходят счётной строкой в
   `~/.claude/logs/worker-hook-noise.log` — не молча выброшены, но и не ломают парность.
2. **Голый `?` из формата убран.** Если тип не пришёл — в клетке `?<id>` (`?a8a3d4`), то есть
   «имя не пришло» видно и отличимо от «нет START». Раньше одна клетка означала две поломки.
3. **Непарный `STOP` называет себя сам** — на месте длительности маркер `START?`.
4. **Все чтения, дописывание и ротация — под одним `flock`** (`~/.claude/logs/worker-log.lock`).
5. **Ротация опознаёт событие по дате** (`^- ГГГГ-ММ-ДД ЧЧ:ММ `), а не по дефису: шапка любой
   длины и элементы `tags:` остаются на месте, тело режется правильно, старое уезжает в
   `91-Archive/workers-ГГГГ-ММ.md`.
6. **Имя события сверяется подстрокой в нижнем регистре**, а если его нет — событие определяется
   по форме payload. Переименование поля в харнесе теперь не превращает хук в тишину.
7. **Дамп сырых payload'ов** — постоянная возможность, по умолчанию выключенная: строка `on` в
   `~/.claude/logs/worker-hook-debug.on` включает запись входов в
   `~/.claude/logs/worker-hook-payloads.jsonl` (хвост 400 записей). Именно им доказан пункт про
   форму payload; без него причина не выясняется вообще — хук по построению молчит.

Шапка `_workers.md` описывает новые пометки и прямо говорит, что строки `STOP ?` до 05.08 — это
события конца хода. Старые строки не тронуты: журнал — история, она не переписывается.

## Живая проверка

**Параллельные воркеры после правки** (23:13, два субагента разного типа одновременно):

```
- 2026-08-05 23:13 START general-purpose spawner=stack agent=a4f1ae94 sess=bcd9aeb3 ·
- 2026-08-05 23:13 START Explore      spawner=stack agent=a1fddfe3 sess=bcd9aeb3 ·
- 2026-08-05 23:13 STOP  general-purpose spawner=stack agent=a4f1ae94 sess=bcd9aeb3 · 0м · ok
- 2026-08-05 23:13 STOP  Explore      spawner=stack agent=a1fddfe3 sess=bcd9aeb3 · 0м · ok
```

Пары на месте, типы настоящие, `?` нет.

**Прогон на синтетических payload'ах** (`~/claude-stack/tests/test-worker-log.sh`) — 18 из 18 ok: обычная
пара; `STOP` с типом без `START` → маркер `START?` и `СБОЙ`; не-воркерский `STOP` → в журнале
ничего, в шумовом логе +1; `STOP` без типа но с транскриптом → `?<id>`; `START` без типа →
`?<id>`; переименованные события `SubagentStarted/Stopped` пишутся; `Stop` главного агента
игнорируется; **30 одновременных записей — 30 строк, все типы различимы**; ротация с шапкой
длиннее 20 строк — шапка цела, тело 300, в архиве 103.

**`bash ~/.claude/hooks/stack-doctor.sh` → 417 ok, 1 варн, провалов нет** (порог «не хуже 399/1»
выдержан).

**Что осталось подтвердить на живом:** настоящее событие конца хода после правки. С 22:33 лид ход
не завершал, поэтому не-воркерская ветка проверена пока только синтетикой (кейс 3). Проверка
занимает одну команду после любого следующего конца хода лида: в
`~/.claude/logs/worker-hook-noise.log` должна появиться строка с `sess=bcd9aeb3` (записи с
`sess=s1234567` — от тестов), а в журнале новых `STOP ?` быть не должно. Если нужен ещё и сырой
payload события — положить строку `on` в `~/.claude/logs/worker-hook-debug.on` и вернуть `off`
после разбора.

## Проверки для доктора (добавляет лид)

1. **Регрессия голого `?`:** `grep -E ' (START|STOP ) \? ' _workers.md` по строкам новее
   2026-08-05 — не должно быть ни одной. Голый `?` = не-воркерское событие снова пишется в журнал
   либо формат откатили.
2. **Поведенческий тест «не-воркер не пишется»:** подать хуку
   `{"hook_event_name":"SubagentStop","session_id":"dt","agent_id":"aphantom123","stop_hook_active":false,"last_assistant_message":"x"}`
   → в журнале строк не прибавилось, в шумовом логе прибавилась одна.
3. **Поведенческий тест гонки:** 10 одновременных `SubagentStart` в временной vault → ровно 10
   строк. Ловит исчезновение `flock`.
4. **Поведенческий тест ротации:** шапка длиннее 20 строк + 402 строки тела → шапка цела
   (включая `- board`/`- workers`), тело 300, архив непустой. Ловит возврат старой формулы шапки.
5. **Маркеры на месте:** `STOP` без парного `START` обязан содержать `START?`, `START`/`STOP` без
   типа — `?<id>`. Ловит откат к формату, в котором две разные поломки выглядят одинаково.
6. **Дамп не забыт включённым:** если в `~/.claude/logs/worker-hook-debug.on` есть строка `on` —
   варн. Дамп пишет промпты и реплики целиком, его место — время разбора, а не постоянная работа.

Готовый код всех четырёх поведенческих тестов лежит в
`~/claude-stack/tests/test-worker-log.sh` (кейсы 3, 8, 9 и 2/4/5 соответственно) — переносится в доктор
почти дословно.
