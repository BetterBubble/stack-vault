# Аудит стека круг 1 — находки ревизора-ломателя 2026-08-09

Только чтение. Всё воспроизведено запуском `guard.sh` на пробах и грепом по проводке хуков.
Пробы лежали в скратчпаде сессии, вход собирался как `pl` в `stack-doctor.sh`
(`AGENT_ROLE`, `AGENT_CODE_ROOT`, `AGENT_WORKTREE_ROOT`, `AGENT_VAULT`, `GUARD_TEST_RUN=1`).
Три находки отсортированы по последствию, дороже — выше.

## 1. Механизм подталкивания застрявшей роли (`stop-nudge.sh`) НЕ подключён ни к одному событию

**КЛАСС:** мёртвый хук, зарегистрированный на событие, которое не приходит (4) + норма обещает
механизм, которого фактически нет (1).

**ЧТО.** Целевая картина работы (`10-Areas/area-celevaya-kartina-raboty.md:49-50`) называет прямым
требованием: *«Лид, который сказал "пишу план" и замолчал, — это поломка. Нужен механизм
подталкивания, а не надежда на дисциплину»*. Этот механизм написан, выверен по 5612 ходам истории
транскриптов и покрыт юнит-тестами доктора — это `~/.claude/hooks/stop-nudge.sh`. Но он не
подключён ни к событию `Stop`, ни к какому другому в `settings.json`. Событие `Stop` вызывает
только `stop-reminder.sh` (страховка канала сигналов), и тот `stop-nudge` не зовёт.

**ВОСПРОИЗВЕДЕНИЕ.**
```
$ grep -rn "stop-nudge" ~/.claude/settings.json
# (пусто — в settings.json нет ни одной ссылки)

$ grep -n '"command"' ~/.claude/settings.json | grep -i stop
308:  "command": "/Users/bubblemac/.claude/hooks/stop-reminder.sh"   # это единственный Stop-хук

$ grep -n "stop-nudge\|nudge" ~/.claude/hooks/stop-reminder.sh
# (пусто — stop-reminder не вызывает stop-nudge)

# stop-nudge упоминается ТОЛЬКО в собственном тесте доктора:
$ grep -rln "stop-nudge" ~/.claude ~/claude-stack
~/.claude/hooks/stop-nudge.sh
~/.claude/hooks/stack-doctor.sh   # только прогон юнит-тестов, не проводка
```
Доктор при этом зелёный: он проверяет `[ -x stop-nudge.sh ]` и гоняет юнит-тесты
(`stack-doctor.sh:1766,1802,1873`), но НЕ проверяет, что хук зарегистрирован на событие. То есть
диагностика подтверждает «скрипт исправен», а вопрос «подталкивание реально происходит» не
задаётся вовсе — проверка, которая не может провалиться на этой поломке.

**ПОСЛЕДСТВИЕ.** Ровно тот дефект, который целевая картина называет поломкой: роль объявляет
действие и молчит, работа встаёт, человек узнаёт об этом, только подойдя к компьютеру. Механизм,
построенный против этого, не срабатывает никогда. Прямо бьёт по «работа идёт сама и не
останавливается».

**ЧТО ЧИНИТЬ.** Добавить `stop-nudge.sh` в `settings.json` в блок `Stop` вторым хуком рядом со
`stop-reminder.sh` (оба на одно событие допустимы). Затем в `stack-doctor.sh` добавить проверку,
что `stop-nudge.sh` присутствует среди команд `Stop` в `settings.json`, — иначе следующая
регрессия снова пройдёт мимо доктора.

## 2. Кнопки стопа (`AGENTS_OFF`, `AUTONOMY_OFF`) создаются инструментом Write в обход гейта

**КЛАСС:** дыра гейта (5) + норма обещает механизм, которого нет (1).

**ЧТО.** `guard.sh` в шапке и в коде утверждает, что агент не может ни создать, ни снять кнопку
стопа: *«агент не может ни создать, ни удалить ни одну из них»* (строки 34-37, 1769-1776,
1804-1831). Но вся эта защита живёт ТОЛЬКО в Bash-ветке (`if cmd:`, `removal_hit`). Инструменты
`Write`/`Edit` её не проходят: для них проверки кнопок стопа нет. Значит агент создаёт
`~/.claude/AGENTS_OFF` или `~/.claude/AUTONOMY_OFF` инструментом `Write` — и это разрешается.

**ВОСПРОИЗВЕДЕНИЕ** (полный вывод пробы, HOME подменён на временный, живой стоп не тронут):
```
Write -> ~/.claude/AGENTS_OFF (director):   ALLOW
Write -> ~/.claude/AUTONOMY_OFF (lead):     ALLOW
Bash touch ~/.claude/AGENTS_OFF (lead):     deny   <- Bash-ветка ловит, Write — нет
```

**ПОСЛЕДСТВИЕ.** Инвариант «рубильник целиком принадлежит человеку» ложен. Агент (или сорвавшийся
цикл) создаёт `AGENTS_OFF` через `Write` и замораживает ЛЮБУЮ запись всеми ролями — включая
собственную починку, — а снять не может (`rm` заблокирован, `Write` удалять не умеет). Это ровно
та паника-паралич без человека рядом, которую конструкция объявляет предотвращённой. Через
`AUTONOMY_OFF` тем же путём глушится прод и пуш. Бьёт по обеим половинам цели: «не
останавливается» и «агент не уходит в произвол».

**ЧТО ЧИНИТЬ.** В `guard.sh` в ветке `if tool in ("Edit","Write","MultiEdit","NotebookEdit")`
(рядом с A2/FRONTMATTER, ~строка 1850/1915) добавить проверку `file_path`: если разрешённый путь
равен `~/.claude/AGENTS_OFF` или `~/.claude/AUTONOMY_OFF` — `deny` с тем же текстом, что в
Bash-ветке. Создание кнопки должно быть недоступно ни одним инструментом записи, а не только Bash.

## 3. При включённом `AGENTS_OFF` запись через taiga/wiki/helm НЕ блокируется — гейт до них не доходит

**КЛАСС:** норма/комментарий обещает покрытие, которого нет (1) + мёртвый код (4).

**ЧТО.** `guard.sh:52-59` заявляет, что при активном `AGENTS_OFF` через разбор идёт ВСЁ, и полный
стоп *«обязан ловить и те write-инструменты MCP, которых в списке ниже нет и не будет (wiki, taiga,
любой новый сервер)»*. Внутренний код это и делает (`MCP_WRITE_NAME`, строки 910-918). Но
`settings.json` вызывает `guard.sh` только для фиксированного набора инструментов
(`PreToolUse.matcher`, строка 293):
`Edit|Write|MultiEdit|NotebookEdit|Bash|mcp__serena__|mcp__basic-memory__|mcp__ssh-manager__`.
Инструменты `mcp__taiga__*`, `mcp__wiki-mcp__*`, `mcp__helm-analyst__*` под матчер не попадают —
хук для них не запускается вовсе, и «ловит всё» никогда не исполняется.

**ВОСПРОИЗВЕДЕНИЕ.** Если бы `guard.sh` был вызван при `AGENTS_OFF`, он бы отказал (код работает):
```
taiga create_issue: deny    wiki create_page: deny    helm apply: deny    serena replace: deny
```
Но матчер `settings.json` для этих серверов хук не поднимает (проверяется чтением
`settings.json:291-302` — единственный блок `PreToolUse`, других регистраций нет). То есть в живой
работе `deny` выше не наступает. Косвенное подтверждение, что удаления таких серверов держит НЕ
гейт, а список `deny` прав: `settings.json:206-210` (`mcp__taiga__delete_*`,
`mcp__wiki-mcp__delete_page`) — но create/update там нет.

**ПОСЛЕДСТВИЕ.** Аварийный стоп неполон: при нажатом `AGENTS_OFF` агент всё ещё создаёт и правит
задачи в трекере и страницы вики. Слабее, чем находки 1-2 (срабатывает только в момент аварийного
стопа), но это ровно та половина цели — «честно, с проверками» — и норма прямо обещает обратное.

**ЧТО ЧИНИТЬ.** Расширить `PreToolUse.matcher` в `settings.json` так, чтобы под `AGENTS_OFF`
`guard.sh` видел все MCP-серверы (добавить `mcp__taiga__|mcp__wiki-mcp__|mcp__helm-analyst__`, а
лучше — общий `mcp__`, раз гейт уже умеет пропускать чтение). Либо честно переписать комментарий
`guard.sh:52-59`, убрав обещание покрывать wiki/taiga/новые серверы, — но это оставит аварийный
стоп дырявым, поэтому предпочтительнее матчер.

## Что я проверил и нашёл исправным (для следующего круга)

  вырезано осознанно (`guard.sh:1254-1267`), прод для не-субагента держит норма (устный ОК), а не
  гейт. Субагенту тот же вызов отказывается (`ВОРКЕР НЕ МЕНЯЕТ ПРОД`) — проверено.
- **Гигиена памяти `stack-vault`:** все `.md` начинаются с `---`, двойных шапок frontmatter нет
  (у `provider-check-2026-08-05.md` четыре `---` — это горизонтальные линейки в теле, шапка одна).
  FRONTMATTER-гейт на `: ` в значениях работает.

- **`gate-check.sh`** вызывается ночным пайплайном (`autonomous-feature.js`), не событием

  Известный тех-долг «нет временного/бюджетного потолка, только `maxAttempts` на цикл гейта»
