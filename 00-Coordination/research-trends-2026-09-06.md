# Ресерч актуальных технологий — 06.09.2026

Разведка по заказу: свежее за август–сентябрь 2026, применимо к нашему стеку (компания ролей в tmux, basic-memory, хуки-гейты, Remote Control, fable-5, ночная автономия). Не пересказ чейнджлога, а «что из этого ложится в наш сценарий».

## 1. Claude Code 2.1.220 → 2.1.261: что взять

Источник: [официальный changelog](https://code.claude.com/docs/en/changelog), релизы августа — 4 сентября 2026.

### 1.1. Снят часовой лимит фоновых команд (~2.1.25x)
- **Что:** background-команды больше не убиваются через час — работают до выхода процесса.
- **Зачем нам:** ночные прогоны. Раньше длинный тест/сборка/мониторинг в фоне умирал по таймауту и агент терял результат.
- **Как включить:** ничего — уже работает. Но стоит убрать из наших регламентов/скиллов (`autonomous-feature`) обходные приёмы «дробить длинное на куски до часа», если они есть.
- **Риск:** зависший процесс теперь висит вечно; ночному прогону нужен свой таймаут-контроль (у нас есть мониторинг сервера — П.10, добавить проверку висящих фонов).

### 1.2. `bashOutputMaxChars` / `taskOutputMaxChars` до 128K (2.1.261)

> ⚠️ **Проверено 06.09 применением: в settings.json такого ключа НЕТ** (валидатор схемы 2.1.261
> отверг «Unrecognized field»). Скорее всего живёт env-переменной — выяснить точное имя перед
> повторной попыткой; пункт не применён.
- **Что:** сколько вывода команды/фоновой задачи агент получает inline, прежде чем оно уедет в файл.
- **Зачем нам:** воркеры на сервере регулярно теряли хвосты больших выводов (логи, тесты) — это одна из причин «сбоев bash у агентов» из П.5.
- **Как включить:** в `settings.json`: `"bashOutputMaxChars": 128000` — но не бездумно: большой inline-вывод жрёт контекст. Разумно поднять до ~64K для лидов, воркерам оставить дефолт.
- **Риск:** ускоренное сгорание контекста в длинных сессиях (деградация внимания после ~120k токенов — см. §2.3).

### 1.3. `/skill-doctor` (2.1.261)
- **Что:** показывает, какие загруженные скиллы не используются и сколько контекста стоят.
- **Зачем нам:** у нас ~20 скиллов, включая две заглушки (`morning`, `wrap`) — они грузятся в каждую сессию каждого агента компании. Это прямые токены впустую, умноженные на число ролей.
- **Как включить:** прогнать `/skill-doctor` в рабочем и стековом контуре, вычистить/сузить триггеры по результату.
- **Риск:** минимальный; не удалять заглушки, если привычные обращения ещё живы — лучше сжать их текст.

### 1.4. Кэш промпта: диагностика и TTL (2.1.260, 2.1.25x)
- **Что:** `/cost` теперь объясняет причины cache miss (изменились tool definitions, истёк TTL); появились `promptCacheTtl` / `subagentPromptCacheTtl` и `experimental.cacheTtl` в frontmatter агента.
- **Зачем нам:** компания ролей — это много длинных системных промптов (персоны, CLAUDE.md, скиллы). Cache miss на каждом ходе — заметные деньги. Наши хуки, если они динамически меняют окружение/tool defs, могут ломать кэш — теперь это видно.
- **Как включить:** (1) прогнать `/cost` после типовой сессии ГД и посмотреть причины миссов; (2) для долгоживущих ролей в tmux поставить `promptCacheTtl: 1h`; (3) воркерам — дефолтные 5m.
- **Риск:** длинный TTL чуть дороже за запись кэша; окупается только на реально долгоживущих сессиях (наш случай — tmux-роли живут часами).

### 1.5. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` + хуки `PreModelSwitch`/`PostModelSwitch`
- **Что:** принудительная модель для всех сабагентов одной переменной; хуки на смену модели (можно блокировать/подтверждать).
- **Зачем нам:** экономика компании — воркеров (`explorer`, `verifier`) можно принудительно посадить на дешёвую модель, не трогая frontmatter каждого; `PreModelSwitch` — гейт против случайного апскейла на дорогую модель в ночном прогоне.
- **Как включить:** в окружение ночного прогона `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=claude-sonnet-5` (или haiku для разведки); хук `PreModelSwitch` в `guard.sh`-стиле, если захотим жёсткий потолок стоимости.
- **Риск:** verifier на слабой модели может пропускать реальные проблемы — форсить только разведку, не проверку.

### 1.6. `--permission-prompts none` (2.1.259)
- **Что:** для unattended-хостов: всё, что потребовало бы подтверждения, автоматически отклоняется вместо зависания.
- **Зачем нам:** ночная автономия на сервере. Сейчас незакрытый permission prompt = роль стоит до утра. С этим флагом она получает отказ и идёт дальше по очереди задач (что ровно наша модель «заблокированное — в ждёт решения, беру следующее»).
- **Как включить:** в запуск ночных tmux-сессий ролей добавить флаг. Дневные интерактивные сессии — без него.
- **Риск:** отказ там, где человек сказал бы «да» — утром надо читать лог отказов; наши allowlist-права должны покрывать штатные операции заранее (скилл `fewer-permission-prompts` в помощь).

### 1.7. Remote Control: живой стриминг + починки (2.1.24x–261)
- **Что:** live-стриминг tool calls foreground-сабагентов в Remote Control, исправлены stale permission mode, доставка очереди уведомлений, поддержка TLS-proxy; `/remote-control` и `/advisor` появились текстовой формой в headless.
- **Зачем нам:** RC только что включён — теперь с телефона видно не только ГД, но и что делают его сабагенты вживую. Это закрывает «минимум ручной возни»: разметку планов ГД можно делать с телефона.
- **Как включить:** обновиться до 2.1.261 (часть починок именно там) и проверить RC-сценарий на tmux-сервере.
- **Риск:** голоса в RC всё ещё нет — это подтверждённо самый запрашиваемый недостающий кусок ([explainx](https://explainx.ai/blog/claude-code-mobile-remote-control-phone-guide-2026)); наш голосовой контур (П.9) остаётся своим, не ждать нативного.

### 1.8. Мелочи, которые тоже наши
- **Workflow tool** теперь стоит ~1k токенов промпта вместо 5.7k — воркфлоу стали дешевле держать включёнными.
- **`/goal` check-ins** с backoff 30m→1h→2h — меньше шума в длинных задачах (ложится в наш П.2 про болтливость).
- **`/diff`** — фуллскрин-панель незакоммиченных правок; удобно для ревью перед доставкой ветки.
- **`--append-subagent-system-prompt-file`** — большие персоны ролей можно отдавать файлом, не строкой запуска.
- **zstd-бинарь** (~75 MB вместо 340 на Linux x64) + lazy loading — меньше RAM на сервере с десятком tmux-ролей (наш П.10 про RAM).

## 2. Практики мульти-агентных стеков (последние ~6 недель)

Источники: [Tembo](https://www.tembo.io/blog/claude-code-multi-agent-orchestration), [Shipyard](https://shipyard.build/blog/claude-code-multi-agent/), [Developers Digest](https://www.developersdigest.tech/blog/claude-code-agent-teams-subagents-2026), [Promptessor](https://promptessor.com/blog/claude-code-agent-teams-examples-and-multi-agent-workflows-for-parallel-development-in-2026), [SmartScope](https://smartscope.blog/en/generative-ai/claude/claude-code-best-practices-advanced-2026/).

### 2.1. Хуки как гейты качества внутри Agent Teams
- **Что:** сообщество активно использует `TaskCreated` / `TaskCompleted` / `TeammateIdle` хуки: на `TaskCompleted` — автозапуск проверки, на `TeammateIdle` — автоподхват следующей задачи из очереди.
- **Зачем нам:** это ровно наша схема «ГД раздаёт — лид берёт», но сейчас она держится на дисциплине промптов. Хук `TeammateIdle` делает подхват следующей незаблокированной задачи механическим — то, что мы в П.11 налаживали руками.
- **Как включить:** добавить в `settings.json` контура director хук на `TeammateIdle`, который читает доску и отдаёт следующую карточку; на `TaskCompleted` — триггер контролёра перед закрытием.
- **Риск:** хук-автоподхват без веса задачи может дать лиду крупную работу без плана — гейт должен уважать нашу шкалу весов.

### 2.2. Оценка топологий: у нас supervisor, и это правильно
- **Что:** в проде доминируют 5 паттернов (fan-out, pipeline, debate, supervisor, swarm) с разной стоимостью координации. Консенсус: supervisor (наш ГД+лиды) — лучший для разнородных задач; debate (двое критикуют друг друга) — лучший для ревью регламентов.
- **Зачем нам:** подтверждение архитектуры + идея: наши «два critic с оппонированием» на крупных задачах — это debate-паттерн, сообщество рекомендует давать критикам явно противоположные мандаты («ты ищешь лишнее», «ты ищешь недостающее»), а не двух одинаковых.
- **Как включить:** в `working-model.md` §критики — прописать разные мандаты двум критикам.
- **Риск:** нет; изменение на строку регламента.

### 2.3. Контекст: `/handoff` вместо перегруза, деградация после ~120k
- **Что:** зафиксирован порог ~120k токенов, после которого качество заметно падает ещё ДО компакта. Паттерн `/handoff` — не сжимать сессию, а генерить передаточный документ (цель следующей сессии, указатели на артефакты без дублирования содержимого) и начинать новую. Плюс правила компакта в CLAUDE.md: что именно сохранять (изменённые файлы, фаза, команды тестов, решения).
- **Зачем нам:** наш `checkpoint` — это ровно handoff, сделанный раньше моды. Но правил компакта в CLAUDE.md у нас нет — авто-компакт долгоживущей tmux-роли сейчас решает сам, что выкинуть.
- **Как включить:** секция «Правила компакта» в CLAUDE.md контуров (сохранять: текущая карточка, вес, список затронутых файлов, «не трону», статус доски). 3–5 строк.
- **Риск:** нет.
- **Оговорка:** авто-компакт для 1M-моделей улучшен в сентябрьских релизах (компакт ближе к лимиту, recovery-компакт не таймаутится) — порог 120k актуален для качества, не для стабильности.

### 2.4. Один уровень вложенности сабагентов — помнить при проектировании
- **Что:** сабагенты не спавнят сабагентов (ограничение SDK). Лид, запущенный как сабагент, не поднимет воркера.
- **Зачем нам:** наша компания это обходит через Agent Teams (тиммейты — полноценные сессии и спавнить могут), но при проектировании ночных прогонов через `Agent` tool это стреляет.
- **Как включить:** зафиксировать в `agent-company.md` как известное ограничение: воркеров спавнит только тот, кто сам тиммейт, не сабагент.

## 3. Модельные новости: линейка Fable

Источники: [Anthropic — Fable 5.1](https://www.anthropic.com/claude-fable-and-mythos-5-1), [Vellum](https://www.vellum.ai/blog/claude-fable-5-and-mythos-5-benchmarks-explained), [eesel](https://www.eesel.ai/blog/claude-opus-5-vs-fable-5), [the-decoder](https://the-decoder.com/anthropics-claude-fable-5-1-promises-better-coding-and-research-at-up-to-45-percent-less/), [DataCamp](https://www.datacamp.com/blog/claude-fable-5-1).

### 3.1. Вышла Fable 5.1 — главная новость для нас
- **Что:** `claude-fable-5-1` — новый дефолт линейки Fable (в Claude Code с 2.1.257–258), 1M контекста, $10/$50 за Mtok, заявлено «до 45% дешевле» на исследовательских задачах за счёт эффективности. На агентных бенчах прирост кратный: Terminal-Bench-Science 24.7→52.6%, Terminal-Bench 4.0 42→55.8%, AutomationBench 17.1→31.4%.
- **Зачем нам:** мы на fable-5 — апгрейд почти бесплатный по усилию (сменить model id в конфиге ролей), а именно агентные/терминальные сценарии — наш профиль.
- **Как включить:** заменить `claude-fable-5` на `claude-fable-5-1` в конфиге контуров; день погонять параллельно на некритичных задачах.
- **Риск:** свежая модель — возможны изменения повадок (многословность, другое отношение к разрешениям); наши хуки-гейты это страхуют.

### 3.2. Fable vs Opus в агентных сценариях — консенсус сообщества
- **Fable сильнее:** размытые постановки, исследование, длинный горизонт, незнакомые инструменты «из коробки», top score на SWE-Bench Pro (80.3% vs 69.2% у Opus 4.8) и FrontierBench.
- **Opus сильнее:** сходящиеся задачи с внятными критериями успеха, цена/латентность, координация толп фоновых агентов. Формула из практики: «Fable для exploration, Opus для convergence»; Opus при этом отмечен как излишне осторожный в security-задачах, Fable — как менее эффективный по токенам на больших оркестрациях.
- **Для нашей схемы:** ГД/лиды (синтез, размытые постановки) — Fable; воркеры-исполнители с чёткой постановкой — Opus/Sonnet дешевле и не хуже. Сейчас у нас Fable везде — это переплата на воркерах.

### 3.3. Effort
- **Официальная рекомендация:** для кодинг-агентов стартовать с `xhigh`; `high` — нижняя граница для задач, требующих интеллекта; `medium` — только ради экономии. Дефолт — high.
- **Нового в CC:** effort теперь сохраняется per-model, а `s` в `/effort` меняет effort только для текущей сессии — можно безопасно экспериментировать.
- **Для нас:** ГД и критики — high/xhigh; explorer-разведка — medium честно достаточно.

## 4. Прорывные инструменты месяца

Честно: **настоящего прорыва в августе–сентябре нет** — месяц эволюционный, и тащить хайп ради пункта не буду. Два кандидата с оговорками:

### 4.1. OpenCode — мультифронтенд-агент со своим провайдером
- **Что:** [агент](https://codepick.dev/en/guides/ai-coding-agents-2026-roadmap/) с одним ядром и фронтами: терминал, десктоп, IDE, браузер; модель и ключ свои.
- **Зачем нам:** почти незачем — наш стек глубже интегрирован с Claude Code (хуки, teams, RC). Ценность одна: запасной аэродром, если понадобится независимость от вендора. Наблюдать, не внедрять.
- **Риск внедрения:** потеря всей обвязки (гейты, память, компания) ради абстрактной переносимости.

### 4.2. Strategic Compact / handoff-паттерн как скилл
- **Что:** [скилл](https://mcpmarket.com/tools/skills/strategic-context-compactor), предлагающий `/compact` на естественных рубежах (закончена разведка, закрыт дебаг), а не по заполнению окна.
- **Зачем нам:** сам скилл не нужен — идея нужна: компакт по рубежам задачи. У нас рубежи формализованы (сверка постановки → работа → доставка) — вставить подсказку компакта на рубеже в регламент лида. Реализация своя, 3 строки.

## Топ-3 «включить прямо сейчас» (польза/усилие)

1. **Перейти на Fable 5.1** (§3.1) — смена одной строки конфига, кратный прирост именно на терминально-агентных задачах и заявленное удешевление. Заодно снять переплату: воркеров — на Opus/Sonnet через `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` (§1.5).
2. **Ночной набор:** `--permission-prompts none` для unattended-прогонов + снятый лимит фоновых команд + `bashOutputMaxChars` для лидов (§1.1, 1.2, 1.6) — три настройки, закрывающие главные причины «ночь встала» и «воркер потерял вывод».
3. **`/skill-doctor` + правила компакта в CLAUDE.md + кэш-TTL 1h для tmux-ролей** (§1.3, 1.4, 2.3) — гигиена контекста и денег: один прогон диагностики, пять строк регламента, две строки настроек.
