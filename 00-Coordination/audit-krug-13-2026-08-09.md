## 1. Полный стоп `AGENTS_OFF`: правило раннеров обходится стандартным идиомом `PGPASSWORD=… psql -c "UPDATE…"` — анкер ищет раннер только в начале или после разделителя

**КЛАСС:** дыра гейта, худшее направление (запись мимо аварийного стопа), тир НЕВИННЫХ форм — не
принятый долг. Тот же корень, что цепочка git-клауз (к6→к9): детектор привязан к ПОЗИЦИИ, а не судит
всю строку. Для git это уже закрыто перебором `git_writes_anywhere`; правило раннеров (заведено к11)
приёма не получило и с рождения несёт анкер `(?:^|[|;&]\s*|\bxargs\s+|\bsudo\s+|\benv\s+)`.

**ЧТО.** `runner_writes` (`guard.sh:1100`) ищет раннеры через `RUNNER.finditer`, но `RUNNER`
(`guard.sh:1055`) матчит только раннер, стоящий в НАЧАЛЕ строки, после шелл-разделителя, `xargs`,
`sudo` или команды `env`. Присваивание-префикс переменной (`PGPASSWORD=…`, `MYSQL_PWD=…`, любое
`ИМЯ=знач раннер …`) и командная подстановка (`$(…)`, обратные кавычки) в анкер не входят — раннер не
находится, `runner_writes` возвращает False, запись проходит. `PGPASSWORD=…`/`MYSQL_PWD=…` — это
СТАНДАРТНЫЙ идиом передачи пароля БД, агент пишет его сам собой при любой записи в базу.

**ВОСПРОИЗВЕДЕНИЕ** (песочный `HOME` с нажатым `AGENTS_OFF`, роль `lead`, настоящий `guard.sh`,
cwd — песочный git-репо; контроли: `git commit` DENY, `git log` ALLOW):
```
PGPASSWORD=secret psql -c "UPDATE t SET x=1"   => ALLOW  ← запись в БД мимо стопа (ходовой идиом)
MYSQL_PWD=x mysql -e "DROP TABLE t"            => ALLOW  ← DROP мимо стопа
x=$(psql -c "DROP TABLE t")                     => ALLOW
x=`psql -c "DROP TABLE t"`                       => ALLOW
x=$(kubectl delete pod foo)                      => ALLOW
FOO=1 ./deploy.sh                                => ALLOW  ← прямой запуск скрипта мимо стопа
x=$(make deploy)                                 => ALLOW
асимметрия (git судится по всей строке — ловится):
FOO=bar git commit -m x                          => DENY
x=$(git commit -m x)                             => DENY
контроли (раннер в начале / после разделителя): psql "DROP…" => DENY · echo x | psql "DROP…" => DENY
· A=1 B=2 docker rm foo => DENY (случайно: «rm» ловит WRITE_VERB, не правило раннеров)
```
`PGPASSWORD=secret psql "SELECT 1"` (чтение) тоже ALLOW — но это верно, потому что случайно: правило
раннеров его вообще не видит. То есть под этим префиксом стоп не судит раннер НИКАК.

**ПОСЛЕДСТВИЕ.** Инвариант «при `AGENTS_OFF` не меняется ничего» ложен для стандартного идиома работы
с БД и для `ИМЯ=знач ./script`/`make`/`npm`. Это не самообфускация (принятый долг к10 — про бинарь в
ПЕРЕМЕННОЙ, `G=git; $G commit`): здесь раннер и запись — литералы, префикс безобиден. Тир к11-f2
(невинные формы), не тир принятого долга. Асимметрия `FOO=bar git commit` DENY / `PGPASSWORD=… psql
"UPDATE"` ALLOW — доказательство недосмотра, а не выбора: тот же префикс git ловит.

**ЧТО ЧИНИТЬ.** Классом, и класс в файле уже есть: судить раннеры так же, как git — перебором ВСЕХ
вхождений по всей строке, не по анкеру позиции. Минимально — добавить в анкер `RUNNER` присваивание-
префикс (`(?:\w+=\S+\s+)+`) и открытие подстановки (`\$\(`, обратная кавычка), но перечень контекстов
отстанет так же, как перечень глаголов; правильнее — искать раннер как токен в позиции команды в
каждом сегменте (у стоп-классификатора уже есть разбор сегментов для SSH). Юнит доктора:
`PGPASSWORD=x psql -c "UPDATE…"` и `x=$(make deploy)` под стопом обязаны дать DENY.

## 2. `morning.md` шаг 1 хардкодит `~/tacticum` — при том что тот же файл запрещает хардкод, а `AGENT_CODE_ROOT` заведён ровно для переносимости

Круг 12 назвал это гипотезой («норма переносимости на команды не записана») — но она записана, и в
этом же файле.

**ЧТО.** `morning.md:25`: «Найди все git-репо в `~/tacticum`» — путь захардкожен. При этом

чтобы корень кода не был вшит, и CLAUDE.md обещает «сменишь работу → сменишь профиль, стек не трогаешь».

**ВОСПРОИЗВЕДЕНИЕ.**
```
grep -n 'tacticum' morning.md            => :25 «все git-репо в ~/tacticum» (хардкод)
grep -n 'не хардкод\|НЕ хардкодь' morning.md catchup.md => morning:22, catchup:22 (норма против)
grep -n AGENT_CODE_ROOT agent-stack.conf => :6 переменная существует ради этого
```

**ПОСЛЕДСТВИЕ.** Смена работы (новый профиль ставит `AGENT_CODE_ROOT` в другой корень) молча сломает
утренний флоу: `/morning` пойдёт сканировать `~/tacticum`, которого уже нет, найдёт ноль репо и не
скажет почему. Низкая частота (смена работы редка), но это ровно та поломка, против которой заведён
и конфиг, и правило домов. Дёшево: `~/tacticum` → `"${AGENT_CODE_ROOT:-$HOME/tacticum}"` (или прямая
ссылка на переменную конфига).
