# Аудит полноты миграции Claude → Codex

Проверено: локальный `~/.codex`, личный сервер `stack`, Codex app, импорт ролей/хуков/сессий, девять MCP, канал на `go-dev-3`. Серверы не изменялись. Состояние снято 01.10.2026 в 09:53–10:02 МСК; конфиг в это время продолжал дополняться лидом.

### 🗑 УБРАТЬ (лишнее)

- `~/.codex/hooks.json` §`Stop` — активны `voice-response.sh` и `tg-reply-reminder.sh` → Президент прямо исключил Telegram и подобные каналы из текущего скоупа, а эти два хука запускаются в конце каждого хода → убрать их регистрации из Codex-контура, сами скрипты можно оставить как откатный материал.

### ➕ ДОБАВИТЬ (пропущено)

- `Codex app` §Connections — подключённого удалённого хоста нет: `list_projects` 01.10 09:53 показал только `hostId: local`, хотя SSH-алиас `stack` уже есть → без этого Александр не может из текущего приложения открыть серверный Codex и 50 импортированных сессий → добавить хост `stack` в Settings → Connections и проверить открытие `~/tacticum-vault` и `~/stack-vault`.
- `stack` §Remote Control — daemon жив и persistent, но pairing получил HTTP 403 `Multi-factor authentication required` → прямой удалённый контроль не готов → после включения MFA в ChatGPT повторить pairing и проверить вход из приложения; до этого честно считать рабочим только SSH-host путь.
- `~/.codex/hooks/guard.sh:64,137–146` + `~/.codex/hooks/session-start.sh:19–32` — роль берётся из `AGENT_ROLE` либо имени tmux-окна, а custom agents Codex не задают ни то ни другое; кроме того, `is_subagent` исключает любого дочернего агента из A2 → запрет «director не кодит» и регистрация адреса роли в нативном Codex не доказаны и, по механике, не срабатывают → завести Codex-native отображение `agent_id → agent_type` из `SubagentStart` и использовать его в guard/session lifecycle; мутацией доказать блокировку записи директором и разрешение implementer в worktree.
- `~/.codex/hooks.json` vs `~/.claude/settings.json` — при импорте исчезли `PermissionDenied`, `PostToolUseFailure`, `TeammateIdle`; Codex поддерживает `PermissionRequest`, но его в манифесте тоже нет → журналы отказов/сбоев и idle-механика не восстановлены → для поддерживаемых событий сделать Codex-native замену, неподдерживаемые явно записать как принятый разрыв, а не считать «хуки перенесены».
- `~/.codex/agents/` и `/home/alex/.codex/agents/` §приёмка — на обоих хостах уже есть все десять ролей, но фактический smoke доказал только загрузку/спавн `lead`; нет доказательства цепочки `director → lead → worker`, MCP внутри дочернего воркера, записи результата на доску и переживания рестарта → прогнать один сквозной read-only сценарий с конкретными маркерами и проверить доску после закрытия корневой сессии.
- `~/.codex/config.toml` и `/home/alex/.codex/config.toml` §MCP — девять рабочих MCP, включая `fleet`, уже объявлены на обоих хостах, но локальный smoke дал `serena: FAIL — нет активного проекта`, а `fleet` был добавлен после того прогона → активировать реальный проект Serena и вызвать безопасное чтение; через нативный Codex вызвать `fleet.list_workers`; принять только при 9/9 OK.
- `~/claude-stack/tools/codex-remote/README.md` §«Диск» + живая проба `codex-task.sh list` — `go-dev-3` отвечает, login/limits живы (46 %, сброс 06.10), но свободно 2,1 ГБ при пороге запуска 3 ГБ → новая задача сейчас будет отклонена, то есть второй рабочий сервер формально доступен, практически не готов → при отсутствии живых задач очистить кэш штатным `gc-cache`, повторить `list`, затем сделать безопасный минимальный прогон роли.
- `~/.codex/config.toml:5–6` vs `/home/alex/.codex/config.toml` — локально явно `gpt-5.6-sol/high`, сервер наследует default и живой прогон разрешился в `gpt-6.1-sol`; роли задают только effort → один и тот же агент получает разные модели в зависимости от хоста → принять явную Codex-модель для диалоговых ролей и воркеров и прописать одинаково на обоих хостах либо документировать намеренную разницу.
- `/home/alex/.codex/external_agent_session_imports.json` vs локальный аналог — на сервер импортировано 50 Claude-сессий, локально 5 → после подключения SSH-хоста проверить, что 50 доступны в интерфейсе; если нет, импортировать недостающие в тот Codex-home, который реально показывает приложение.
- `tmux work` на `stack` — окна `main` и пять `lead-*` всё ещё запускают `claude`; нативного долгоживущего director/lead-контура Codex нет, есть только daemon, импортное окно и ephemeral custom-agent smoke → определить cutover: старые окна оставить откатом, но поднять и проверить хотя бы один persistent director + lead в Codex; пока этого нет, «компания переехала» неверно.

### ✏️ УЛУЧШИТЬ (переформулировать/структура)

- `~/.codex/agents/director.toml:4`, `lead.toml:4`, `stack.toml:4` — Codex-адаптер теперь явно отменяет `open-lead.sh`/Claude и добавляет все роли/MCP, но ниже одной огромной строкой остаётся полный Claude-канон с `become`, tmux, `~/.claude/hooks` и старым жизненным циклом → вместо конкурирующих инструкций выделить короткий Codex-native runtime adapter/charter; Claude-файл оставить ссылочным каноном поведения, не исполняемым сценарием.
- `~/.codex/hooks.json` §`PreToolUse` и MCP-конфиг §`default_tools_approval_mode = "approve"` — все инструменты девяти MCP одобрены целиком, а механический guard для Codex-ролевой идентичности ещё не доказан → до сквозной мутационной проверки не считать восстановленными прежние границы; как минимум отдельно проверить write-инструменты `ssh-manager`, `wiki-mcp`, `taiga`, `iva-write`, `fleet`.

### ✓ Сверка запрошенных правок

- «директор, лиды и воркеры настроены» → **частично** → десять TOML-ролей есть локально и на `stack`, но сквозной runtime и persistent-сессии не приняты.
- «все настройки как в Claude» → **частично** → AGENTS, skills, 10 основных hook-событий и 50 серверных сессий импортированы; три hook-события потеряны, role env/lifecycle не перенесён, модели расходятся.
- «все инструменты подключены» → **частично** → девять MCP объявлены на обоих хостах; восемь серверных проверены до добавления `fleet`, локально 7/8 старого набора, Serena не активирована; нового полного 9/9 нет.
- «из этого Codex запускать агентов на личном сервере» → **не внесена до конца** → SSH host `stack` отсутствует в Codex app.
- «отправлять задачи учётке на втором рабочем сервере» → **частично** → `go-dev-3` и учётка живы, `codex-task.sh` читает limits/list, но диск ниже порога нового запуска; `fleet` добавлен, но нативный Codex-вызов не принят.
- «Telegram и похожее сейчас не настраивать» → **частично** → отдельный канал не настраивался, но два Telegram/voice Stop-hook всё ещё активны.

### Вердикт

Основа собрана, но как немедленная замена Claude система пока не годится: пользователь ещё не может открыть `stack` из Codex app, границы ролей/хуки не доказаны нативно, а `go-dev-3` ниже дискового порога запуска. До формулировки «восстановлено» критично закрыть доступ из приложения, сквозной agent-smoke с 9/9 MCP и реальный минимальный прогон второго сервера.
