# Разведка: голос ↔ Claude Code на русском

Задача — понять, чем качественно вводить голосом по-русски и чем качественно озвучивать ответы. Разведка, не реализация. Актуальность — сентябрь 2026.

## Главная находка: диктовка уже встроена в Claude Code

В Claude Code CLI есть **встроенная голосовая диктовка `/voice`** — и она **официально поддерживает русский** (`ru` в списке из 20 языков). Это меняет всю картину: половина задачи решена без единой строчки кода.

- Включается `/voice`, язык — настройкой `"language": "russian"` (или `ru`) в settings / `/config`.
- Два режима: **hold** (push-to-talk — держишь Space, говоришь, отпустил — текст в промпте) и **tap** (тап — запись, тап — отправка; с автоотправкой от 3 слов). Клавишу можно перебиндить (`voice:pushToTalk`), для hold-режима лучше модификатор типа `meta+k` — без прогрева key-repeat.
- Транскрипция **живая, в поле ввода**, можно мешать голос и клавиатуру в одном сообщении. Словарь настроен на кодовую лексику (regex, OAuth, JSON), имя проекта и ветки подмешиваются как подсказки распознавания.
- **Не локально**: аудио стримится на серверы Anthropic. Нужен вход через Claude.ai-аккаунт (не API-ключ). Токены и лимиты не тратит.
- **Требует локальный микрофон** — в SSH-сессиях и Claude Code on the web не работает.

Качество русского в этой диктовке отдельно никем не забенчмарчено (движок Anthropic не раскрывает), но раз русский в официальном списке — рассчитан на боевое использование. Проверяется за 5 минут руками: `/voice`, `/config` → language → russian.

### Ограничение: удалённые агенты в tmux

Встроенная диктовка живёт там, где запущен CLI и микрофон. Для сессий **на Linux-сервере в tmux** она не работает (нет локального микрофона у удалённого процесса). Обход — системная диктовка на маке, которая печатает в любое активное окно, включая терминал с ssh/tmux:

- **superwhisper** (~$8.5/мес или $85/год, есть навсегда-лицензия) — офлайн Whisper Large V3 Turbo на M-чипах, 100+ языков включая русский, вставляет текст в любое приложение; в апреле 2026 добавил отдельный **пайп для Claude Code**. Де-факто стандарт этой ниши на маке.
- **MacWhisper** — то же семейство, разовая покупка, русский тоже через Whisper.
- **Wispr Flow** — облачный, быстрый, русский поддерживает, подписка.
- Встроенная диктовка macOS — русский распознаёт заметно хуже Whisper-семейства, не рекомендую как основную.

## STT локально — справка по качеству русского (если захочется своей обвязки)

| Модель | Русский WER (FLEURS) | Скорость на Apple Silicon | Стриминг |
|---|---|---|---|
| whisper.cpp large-v3 | ~4.0% | 5–7× реалтайма (CoreML/Metal) | псевдо (окна ~5 с, шаг 500 мс) |
| large-v3-turbo | близко к v3 на русском | ~5× быстрее v3 | так же |
| **parakeet-tdt-0.6b-v3** (NVIDIA) | **~3.0%** — лучше whisper | до ~60× реалтайма | лучше подходит для реалтайма |
| faster-whisper | те же веса → тот же WER | быстрее referenc-python | псевдо |

Вывод: локальный STT русского — зрелый, parakeet v3 даже точнее whisper large-v3 и на порядок быстрее. Но собирать свою push-to-talk-обвязку имеет смысл только если встроенный `/voice` разочарует по качеству: выигрыш — офлайн и контроль, цена — вечер-два возни с аудиозахватом и вставкой текста.

Важно про «реалтайм»: whisper-семейство режет аудио окнами, честного пословного стриминга нет — для диктовки «записал-отпустил» это неважно, для живого диалога — важно.

## TTS русский — варианты озвучки ответов

| Вариант | Качество русского | Задержка | Цена | Офлайн |
|---|---|---|---|---|
| **edge-tts** (`ru-RU-DmitryNeural`, `SvetlanaNeural`, `DariyaNeural`) | хорошее нейросетевое, «диктор» | ~0.5–1.5 с (сеть) | бесплатно | нет |
| macOS `say -v Milena` (обычная) | разборчиво, но звук 2010-х | мгновенно | бесплатно | да |
| Milena Premium/Enhanced (докачивается в настройках macOS) | заметно лучше обычной, приемлемо | мгновенно | бесплатно | да |
| Piper (`ru_RU-irina/dmitri/denis/ruslan-medium`) | среднее, «понятно, но роботно» | <0.5 с локально | бесплатно | да |
| OpenAI TTS API | хорошее, лёгкий акцент местами | ~1 с | $0.015/1000 зн. | нет |
| ElevenLabs | лучшее на рынке | ~0.5–1 с | дорого (подписка) | нет |

Рекомендация: **edge-tts как основной** (бесплатно, нейроголос, ставится `pip install edge-tts`, никакой регистрации), **`say -v Milena` (Enhanced) как офлайн-фоллбек**. ElevenLabs для озвучки статус-ответов агента — из пушки по воробьям. Единственный риск edge-tts — неофициальный API Microsoft, периодически ломается и чинится сообществом; фоллбек его страхует.

## Озвучка ответов через Stop hook — реалистично, проверено другими

Stop hook получает в stdin JSON с полем **`last_assistant_message`** — финальный текст ответа, транскрипт парсить не нужно. Готовых реализаций много (devilsberg.com, brtkwr.com, cris-m/claude_voice, claude-code-voice-hook и др.) — паттерн отработанный:

```
Stop hook → jq '.last_assistant_message' → фильтр/очистка → TTS → afplay (async)
```

Обязательная обработка (все известные грабли):

1. **Длинные ответы.** Озвучивать целиком нельзя. Практика: до ~300–500 символов читать целиком, длиннее — только первый абзац или первое предложение + «подробности в терминале». (Вариант «суммаризировать через haiku» возможен, но добавляет задержку и стоимость — не для первой версии.)
2. **Markdown и код.** Вырезать код-блоки, таблицы, заголовки, `**`, бэктики, URL — иначе голос читает мусор. Простой sed/python-фильтр; идеальной очистки не будет, редкое форматирование прорвётся — терпимо.
3. **Параллельные сессии перебивают друг друга.** Несколько окон Claude Code = несколько hook'ов = какофония. Лечится lock-файлом (flock) — либо очередь, либо «говорит только один, остальные молчат». Для первой версии достаточно flock + отбрасывание.
4. **Удалённые tmux-сессии.** Hook исполняется на сервере — звука там нет. Честный ответ: озвучку делаем **только для локальных сессий**; для серверных вместо звука — уведомление (это отдельная тема, не сюда).
5. Hook должен запускать проигрывание **в фоне** (`&`, disown) — иначе блокирует Claude Code до конца фразы.

## Честная оценка

**Собирается за вечер с хорошим качеством:**
- Ввод: включить `/voice` + `language: russian` — 5 минут, ноль кода. Проверить качество русского на реальной речи — главный эксперимент вечера.
- Вывод: Stop hook (~50–80 строк bash/python): очистка markdown → усечение → edge-tts Dmitry → afplay, flock от параллели, фоллбек `say -v Milena`. Паттерн многократно реализован другими.

**Будет полурабочим:**
- Озвучка длинных аналитических ответов — любая стратегия усечения иногда режет главное.
- Своя локальная STT-обвязка (parakeet/whisper) — качественно можно, но это уже проект, а не вечер; делать только если встроенный `/voice` подведёт на русском.
- Голос для удалённых tmux-агентов — требует туннеля звука или пуш-уведомлений, отдельная задача.

**Пока делать не стоит — полноценный диалоговый hands-free режим** (говоришь без кнопки, агент отвечает голосом, можно перебивать):
- Честного стримингового STT «как в звонке» локально нет — whisper работает окнами; VAD (детекция конца фразы) на русском в бытовом шуме капризна, будет резать на полуслове.
- Barge-in (перебивание речи агента) требует эхоподавления — колонки глушат микрофон.
- Существующие MCP-решения (voicemode и подобные) заводят каждый обмен репликами через инференс — медленно и дорого, при этом push-to-talk теряет всего одно нажатие клавиши.
- Соотношение затрат к выигрышу против push-to-talk — плохое. Вернуться, когда появится зрелый локальный streaming-ASR для русского.

## Рекомендация: минимальный качественный контур

1. **Ввод:** встроенный `/voice hold` + `"language": "russian"` — push-to-talk на Space/meta+K. Если качество русского разочарует — superwhisper как план Б (офлайн, свой пайп в Claude Code, печатает и в ssh-окна).
2. **Вывод:** Stop hook → очистка → edge-tts `ru-RU-DmitryNeural` → afplay; фоллбек `say -v Milena` без сети; flock от перебивания параллельных сессий; озвучка только локальных сессий.
3. **Не делать сейчас:** диалоговый hands-free, свою STT-обвязку, озвучку удалённых tmux-сессий.
