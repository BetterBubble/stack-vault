Срез: Mac + `stack` + read-only канал `go-dev-3`, 01.10.2026 11:28–11:35 МСК. Конфиги и серверы не менялись. Закрытые пункты старого разбора повторно дефектами не считаются: SSH-host `stack` виден приложению, три lead-сессии работают, десять custom agents и девять рабочих MCP установлены на обоих хостах, Fleet/Serena приняты, Telegram/voice сняты с Codex hooks, нативный реестр и базовый worker guard прошли smoke.

### 🗑 УБРАТЬ (лишнее)

- `/home/alex/.claude/.role-registry` — одновременно зарегистрированы старые Claude и новые Codex-сессии на адресах `lead-aipaas`, `lead-aipaas-platform`, `lead-aipaas-delivery`; в `tmux work` всё ещё живы Claude `main` и пять `lead-*` → после принятого handoff это два владельца одного адреса и ложная картина живости → старые процессы оставить только как явно названный архив/откат, но убрать их из рабочего реестра и запретить им получать новые поручения.

### ➕ ДОБАВИТЬ (пропущено)

- `/home/alex/.codex/hooks/guard.sh:200–208,1076,2440–2508` против локального `~/.codex/hooks/guard.sh:206–228,2475–2545` — серверный guard не разбирает `apply_patch`, хотя серверный `hooks.json` уже матчится на этот инструмент → реальная read-only проба `director + apply_patch` дала на Mac A2 deny, на `stack` — пустой вывод/проход → синхронизировать поддержку `apply_patch` и повторить на `stack` минимум A2, `AGENTS_OFF`, кнопки стопа и frontmatter.
- `Codex app` §thread `director` (`01a0f632-8c04-7212-bb5e-8fe203adb75c`) — статус `notLoaded`, единственный ход остаётся импортным отказом Claude; рабочего Codex-хода директора нет → открыть именно серверного `director`, выполнить read-only онбординг/status и доказать `director → lead → worker` в текущей рабочей памяти.
- `~/claude-stack/roles.zsh:145,167,254–257,287–291` + `HANDBOOK.md:214–217,263–307` — привычные команды `lead`, `open-lead`, `director`, `stack` по-прежнему запускают `claude`, Claude Remote Control и tmux; нативного способа создать новую постоянную top-level роль Codex не найдено → завести один исполнимый Codex-вход для постоянных dialog roles либо явно утвердить новую топологию «persistent director, leads как Codex children» и проверить её на новом адресе, а не только на трёх импортированных сессиях.
- `~/stack-vault` и `~/tacticum-vault` на Mac против одноимённых vault на `stack` — HEAD попарно разные и отсутствуют в object store другой стороны (`cat-file` в обе стороны = no), при этом basic-memory на каждом хосте считает свой `tacticum-vault` default → два Codex-хоста отвечают из разной памяти → до совместной работы объявить один рабочий vault источником правды и настроить безопасную синхронизацию/хендофф; иначе локальный и серверный director расходятся после первого факта.
- `~/claude-stack/tools/codex-remote/README.md` §порог диска + живая `codex-task.sh list` 11:34 — `go-dev-3` всё ещё имеет 2,1 ГБ свободно при минимуме запуска 3 ГБ → старый второй сервер читается, но новую задачу не примет → штатно освободить место и принять минимальным новым `run`, не только `list/limits`.
- `/home/alex/.codex` §managed app-server — три текущие lead-сессии доступны после закрытия хода, но daemon не оформлен systemd-user unit и контролируемого reboot/reconnect smoke нет → не утверждать «переживает рестарт сервера», пока после согласованного рестарта не проверены повторное появление host, открытие тех же thread id и новый ход без реимпорта.
