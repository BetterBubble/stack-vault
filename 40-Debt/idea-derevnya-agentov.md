# Идея: «деревня агентов» — визуальный командный центр

**Заказ Президента 06.09 (дословно):** «я щас представил вот это окно, что-то типа OpenClow…
я вижу всех агентов как персонажей, я могу на них нажимать и видеть их чат, там есть разные
сундучки ещё — типа нажимаю на него, а там типа заметки „ждёт меня", я там же в этом UI все
отвечаю и раскидывается сразу всем агентам». Решение: **запомнить, реализуем потом** («потом
как-нибудь реализуем») — после обкатки RC + телеграма.

## Суть

Веб-страница на сервере стека: офис/деревня, каждый агент — персонаж со статусом
(работает/простаивает/мёртв), клик по персонажу → его живой чат, «сундучок» → очередь
«ждёт меня» с ответами прямо в UI (ответ раскидывается ролям).

## Почему это дешевле, чем звучит — вся начинка уже построена (ночь 06.09)

| Элемент | Готовый механизм |
|---|---|
| статусы персонажей | реестр ролей · watchdog мёртвых ролей · tmux list-windows |
| чат с персонажем | паттерн tg-пульта: ввод → `tmux send-keys` + `[источник]`-префикс; вывод → чтение окна/pipe-pane |
| сундук «ждёт меня» | `_zhdet-resheniya.md` (механическая сборка waiting-queue.sh) |
| ответы из UI | pending/response-файлы (сделаны для TG-кнопок) + канал сигналов |
| статусы задач | `06 — Статусы задач/` |

## План реализации (когда возьмём)

1. **MVP (вечер-два):** функциональный дашборд — карточки ролей со статусами, сундук,
   встроенный чат; FastAPI/статика + WebSocket на сервере стека, доступ с мака и телефона.
2. **Итерации через `/evolve`:** пиксель-арт персонажи, анимации «занят/спит», комнаты-задачи.
3. Референс визуала: [AI Town](https://github.com/a16z-infra/ai-town) (опенсорс, городок с
   агентами) — но он про симуляцию, брать оттуда только рендер-идеи; готового опенсорса
   «дашборд-деревня для реальных Claude Code сессий» на 09.2026 нет (проверено ресерчем ночи).

## Почему отложено

Сначала обкатка построенного (RC-интерфейс + телеграм закрывают 80% «видеть и рулить»);
деревня — следующий крупный UI-заход по слову Президента.
