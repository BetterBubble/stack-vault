# codex-task clean убирает незабранную задачу

**Что случилось (24.09, ai-paas):** лид платформы при срочной уборке диска go-dev-3 сделал `clean` только что
законченной задачи `feat/summarize-chat-prompt-v2` до `fetch`. Ветку спас push из клона, но отчёт Codex
(summary, events) потерян безвозвратно.

**Почему возможно:** `clean` проверяет живые процессы и незакоммиченное в дереве, но не проверяет, забран ли
результат (`fetch`) — каталог прогона `~/codex-runs/<slug>` удаляется вместе с отчётом.

**Что сделать:** `clean` отказывает, если у задачи нет отметки «забрано» (fetch пишет её в meta) и не передан
`--force`; в тексте отказа — «сначала codex-task.sh fetch <id>». Сторож: тест на заглушке, clean без fetch → код ≠ 0.
## Второе, той же ночью: сирота после конца задачи
Задача `feat/receiver-store` закончилась, а её embedded-postgres (тесты) жил ещё 2 ч 15 мин с маркером задачи —
`gc-cache` отказывал («идут задачи»), хотя `list` был пуст; диск go-dev-3 упал ниже порога run. Снял лид вручную
`stop`. **Что сделать:** runner по завершении codex убивает всю группу процессов задачи (по маркеру), а `list`
показывает задачу с живыми процессами как «закончена, но есть процессы: N».
