# Кросс-сессионный канал строим сами, нативного механизма не ждём

**Решение.** Транспорт между окнами-ролями — собственный файловый канал (`signal-*.sh` +
`Monitor` в сессии роли). Нативные механизмы платформы для этой роли **не используются**: ни
фоновый watcher с системным уведомлением, ни Agent Teams. Решение Президента, 25.07.2026;
зафиксировано в прозе `signals.md` и `agent-company.md`, здесь — как решение.

## Контекст

Отдельные сессии-роли не видят друг друга. Требование: событие из одного окна должно **разбудить**
другое окно — не уведомить человека, а заставить агента действовать.

Ключевой факт платформы: **сессия Claude Code действует только во время своего хода. Простаивающая
сессия файлы не опрашивает.** Из этого умерли три поколения канала подряд:

- **v1–v2** — строка в общем `00-Board/_signals.md`, разбор пометкой `[x]`, доставка «когда роль
  сама заглянет». Роль не заглядывала.
- **v3** — тот же общий файл + фоновый watcher с macOS-баннером. Баннер уведомлял **человека**, а
  агенту сигнал доставлялся только когда сессия сама завершит следующий ход, то есть у простаивающей
  роли — никогда. **Улика:** шесть сигналов к `lead-arch` от 24.07 не были подхвачены ни разу,
  потому что окно роли больше не открывалось.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| Фоновый watcher + системное уведомление (v3) | уведомляет человека, а не агента. Лечит симптом, не причину: простаивающая сессия по-прежнему не действует |
| **Agent Teams** как транспорт | тиммейты живут внутри процесса лида — умирают вместе с ним, `/resume` и `/rewind` их не восстанавливают |
| Опрос очереди ходами агента (busy-поллинг) | жжёт контекст и токены, не будит, и разваливается ровно тогда, когда роль занята работой |
| Оставить как есть, «роль сама заглянет на доску» | это и есть v1–v2; за доской в реалтайме никто не следит |
| Ждать нативной доставки от платформы | ждать нечего: механизма нет, а координация нужна сейчас |

## Почему так

`Monitor` убирает **причину**, а не симптом: у него собственный процесс, а его вывод — событие в
чате роли, то есть пробуждение. Проверено вживую 25.07: доставка **<1 с** в сессию, занятую другой
работой, плюс догоняющая выдача очереди, накопившейся пока окно было закрыто.

Про Agent Teams причина сформулирована **вне версий** сознательно. Не «у teams есть баги» — баги
чинят (тот, из-за которого мейлбокс блокировался до 2.1.207, уже исправлен), — а: **несущий принцип
стека «сессия расходник, состояние на durable-доске» требует, чтобы координация переживала
перезапуск.** Транспорт, не переживающий рестарт, который архитектура сама предписывает, не может
стоять в критическом пути.

Прежняя формулировка вето была недатированной и версионной («SendMessage работает через раз») — она
сгнила ровно потому, что объяснение симптому нашлось в чужом changelog'е. Это и есть причина
требовать формулировку вне версий во всех ADR стека.

## Что отменяет

Отменяет watcher-поколение v3 как транспорт: `_signals.md` заморожен (`status: archived`),
легаси-watcher не поднимается (escape hatch `signals-watch-legacy` — только для разбора инцидентов).

## Область действия

- **Запрещено:** Agent Teams как кросс-сессионный транспорт и как гарантия доставки.
- **Разрешено:** Agent Teams как слой воркеров **внутри** одной сессии — воркеры эфемерны по
  дизайну, смертность вместе с лидом для них не минус, зато даёт мгновенный `SendMessage`, общий
  task-list с файловым локом и переиспользование агент-дефиниций.
- Канал **не даёт подтверждений доставки** ни в какой форме. Ждать ответ в цикле запрещено.

## К пересмотру при

- ~~появлении **нативной доставки в простаивающую сессию**~~ — **НАСТУПИЛО, проверено 23.08.2026,
  см. раздел ниже**;
- появлении **восстановления тиммейтов после рестарта лида** (`/resume`) — тогда пересматривается
  кросс-сессионный запрет на Agent Teams. **Проверено 23.08: не наступило**, документация
  по-прежнему говорит «`/resume` and `/rewind` do not restore in-process teammates»;
- если `Monitor` окажется ненадёжным на длинной дистанции.

# Пересмотр 23.08.2026 — нативный канал появился и проверен вживую

**Условие пересмотра наступило.** В Claude Code с версии **2.1.224** есть кросс-сессионная
доставка: инструменты `ListAgents` (кто сейчас доступен) и `SendMessage` (послать в чужую сессию).
Наши версии на 23.08: сервер **2.1.233** — есть, мак **2.1.220** — нет.

## Что показал живой прогон на сервере

Подняты две чистые сессии `alpha` и `beta` в tmux, мониторы **не вооружались**.

| Сценарий | Результат |
|---|---|
| **Адресат жив и простаивает** | ✅ `ListAgents` увидел `beta` как `interactive, idle`. `SendMessage` вернул `success: true`. **`beta` проснулась сама и ответила** — без монитора, без опроса файлов |
| **Адресат закрыт** | ❌ `{"success":false,"message":"Failed to send to beta: HTTP 409 — that Remote Control session may have ended or disconnected"}`. **Сообщение не сохраняется и теряется** |

## Что из этого следует

**1. `Monitor` для пробуждения больше не нужен.** Его работу — разбудить простаивающую сессию —
платформа делает сама. Это снимает и его цену: замер 18.08 дал 550 побудок за 1.6 суток, каждая
полным ходом с перечитыванием контекста.

**2. Файловый канал нужен, но для другого.** Нативный механизм адресует **живую сессию**; наш
канал адресует **роль**, которая может быть сейчас не поднята, и догоняет очередь при следующем
подъёме окна. Это разные гарантии, и вторая нативным механизмом не покрыта вовсе.

**3. Правильная конструкция — гибрид, а не замена:**

- адресат есть в `ListAgents` → **`SendMessage`**, доставка мгновенная и будит;
- адресата нет → **файловый сигнал в инбокс роли**, он дождётся подъёма.

**Что осталось непроверенным:** доставка идёт через серверы Anthropic (ошибка прямо называет
Remote Control), то есть механизм сетевой, а файловый канал локальный. Поведение при потере сети
не проверялось.

**Что это НЕ отменяет:** запрет Agent Teams как кросс-сессионного транспорта остаётся — тиммейты
по-прежнему не переживают рестарт лида, а несущий принцип стека требует, чтобы координация
перезапуск переживала.
