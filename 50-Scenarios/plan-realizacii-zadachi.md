# План реализации задачи

Артефакт №3. Часть [[scenario-raboty-steka]]. **Ключевой артефакт контроля:** по нему Президент видит, что задачу поняли верно, **до** того, как в неё вложили работу.

**Состав:**

1. **Источники постановки** — ссылки на канон/сырье задачи: созвоны, текст заказчика и прочее. Они должны быть записаны и обозначены, что это за источник. Лежат в [[papka-materialov]].
2. **Как агент понял задачу** — текст примерно в один абзац.
3. **Этапы решения** — кратко: разведка → пункты 1, 2, 3, 4 → проверка на тест-стенде (если это подразумевает задача) → сверка с каноном → ещё гейты проверок → готовый PR мне.
4. **Зачем задача и что будет после** — откуда взялась постановка (заказчик, руководитель, иное) и как будет выглядеть структура, когда задача решена: как теперь пользователи будут
   работать с этим скилом, ролью или чем-то ещё.

**Кто пишет.** Лид по своей задаче ([[scenariy-lidy-i-gd]]).

**Апрув.** План **всегда** идёт под апрув Президента. ГД сводит все планы в одну заметку;
апрув пакетом либо комментарии по отдельным задачам. Апрувнутое уходит в работу, остальное —
на второй цикл ([[scenariy-gd-posle-sozvona]]).

**Когда нужен новый.** Если задача пришла с вечера и после созвона **не поменялась** — план
остаётся. **Поменялась — нужен новый план реализации.**

**На выходе.** Сделанное сверяется с **первоначальным** планом, иначе «сделали» ничем не
проверяется.
